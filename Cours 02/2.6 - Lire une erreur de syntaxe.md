# Lire une erreur de syntaxe en Python

## Objectifs

- Comprendre à quel moment Python détecte une erreur de syntaxe.
- Savoir décomposer un message d'erreur (fichier, ligne, curseur, type, description).
- Reconnaître les erreurs de syntaxe les plus fréquentes chez les débutants.
- Distinguer une erreur de syntaxe d'une erreur d'exécution.

## Quand l'erreur est-elle détectée ?

Avant d'exécuter la moindre ligne, Python **lit le fichier au complet** et le traduit en bytecode : c'est l'étape de **compilation**. Si une seule ligne est mal écrite, cette étape échoue et **rien du tout ne s'exécute**.

C'est une nuance importante :

```python
print("Bonjour")
print("Salut"
```

On pourrait croire que `Bonjour` va s'afficher avant l'erreur. **Ce n'est pas le cas** : le message d'erreur apparaît seul, car la compilation n'a jamais abouti.

## Anatomie d'un message d'erreur

Prenons ce fichier `exemple.py` :

```python
age = 20
if age > 18
    print("Tu es majeur")
```

Python affiche :

```text
  File "exemple.py", line 2
    if age > 18
               ^
SyntaxError: expected ':'
```

Ce message se lit en **quatre parties** :

|Partie|Contenu|Ce que ça veut dire|
|---|---|---|
|Fichier|`File "exemple.py"`|Le fichier fautif (utile quand il y en a plusieurs).|
|Ligne|`line 2`|Le numéro de ligne où Python a **détecté** le problème.|
|Extrait + curseur|`if age > 18` et `^`|La ligne recopiée, avec un `^` sous l'endroit exact du problème.|
|Type + description|`SyntaxError: expected ':'`|La catégorie d'erreur et l'explication.|

👉 **La bonne méthode : lire le message de bas en haut.** La dernière ligne dit *quoi*, le curseur `^` dit *où*, le numéro de ligne dit *dans quelle instruction*.

## ⚠️ La ligne signalée n'est pas toujours la ligne fautive

Python signale la ligne où il **se rend compte** du problème, ce qui peut être **après** la vraie erreur. Le réflexe à prendre : si la ligne indiquée semble correcte, **vérifie la ligne précédente**.

## Les erreurs de syntaxe les plus fréquentes

### 1. Les deux-points oubliés

```python
age = 20
if age > 18
    print("Tu es majeur")
```

```text
  File "exemple.py", line 2
    if age > 18
               ^
SyntaxError: expected ':'
```

**Correctif :** ajouter `:` à la fin de la ligne du `if`.

### 2. Une parenthèse jamais fermée

```python
print("Bonjour"
print("Salut")
```

```text
  File "exemple.py", line 1
    print("Bonjour"
         ^
SyntaxError: '(' was never closed
```

**Correctif :** fermer la parenthèse à la ligne 1. Remarque que l'erreur concerne la ligne 1 même si c'est en lisant la ligne 2 que Python a compris qu'il manquait quelque chose.

### 3. Un guillemet manquant

```python
print("Bonjour)
```

```text
  File "exemple.py", line 1
    print("Bonjour)
          ^
SyntaxError: unterminated string literal (detected at line 1)
```

**Correctif :** fermer la chaîne de caractères avec un `"`. *Unterminated string literal* signifie « chaîne de caractères non terminée ».

### 4. Confondre `=` (affectation) et `==` (comparaison)

```python
age = 18
if age = 18:
    print("Pile 18 ans")
```

```text
  File "exemple.py", line 2
    if age = 18:
       ^^^^^^^^
SyntaxError: invalid syntax. Maybe you meant '==' or ':=' instead of '='?
```

**Correctif :** utiliser `==` pour comparer. Python propose lui-même la solution dans le message.

### 5. Une virgule oubliée

```python
total = 10 + 5
print("Total :" total)
```

```text
  File "exemple.py", line 2
    print("Total :" total)
          ^^^^^^^^^^^^^^^
SyntaxError: invalid syntax. Perhaps you forgot a comma?
```

**Correctif :** `print("Total :", total)`.

### 6. Une indentation manquante

```python
age = 20
if age > 18:
print("Tu es majeur")
```

```text
  File "exemple.py", line 3
    print("Tu es majeur")
    ^^^^^
IndentationError: expected an indented block after 'if' statement on line 2
```

**Correctif :** indenter la ligne 3. `IndentationError` est un cas particulier de `SyntaxError` (voir la fiche [Généralités](./2.1%20-%20Généralités.md) au sujet de l'indentation).

## Erreur de syntaxe ou erreur d'exécution ?

Les deux affichent un message, mais elles n'arrivent **pas au même moment**.

```python
print("Debut")
print(mesage)
```

```text
Debut
Traceback (most recent call last):
  File "exemple.py", line 2, in <module>
    print(mesage)
          ^^^^^^
NameError: name 'mesage' is not defined
```

Ici, `Debut` **s'est affiché** : le programme a démarré, puis a planté en cours de route. La syntaxe était valable, mais la variable `mesage` n'existe pas (faute de frappe pour `message`).

|Critère|Erreur de syntaxe|Erreur d'exécution|
|---|---|---|
|Moment|À la compilation, **avant** l'exécution|Pendant l'exécution|
|Le programme démarre-t-il ?|Non, aucune ligne n'est exécutée|Oui, jusqu'à la ligne fautive|
|Mot-clé `Traceback`|Absent|**Présent**|
|Exemples de types|`SyntaxError`, `IndentationError`|`NameError`, `TypeError`, `ZeroDivisionError`|

👉 Le mot **`Traceback`** est le meilleur indice : s'il est là, c'est une erreur d'exécution.

## Méthode de résolution en 4 étapes

1. **Lire la dernière ligne** du message : elle donne le type et la description de l'erreur.
2. **Repérer le numéro de ligne** et ouvrir cette ligne dans VS Code (`Ctrl+G` puis le numéro).
3. **Regarder le curseur `^`** pour cibler le caractère problématique.
4. **Si la ligne semble correcte, vérifier la ligne précédente** (parenthèse ou guillemet non fermé).

💡 VS Code souligne les erreurs de syntaxe **en rouge pendant que tu écris**, avant même de lancer le programme. Corrige les soulignements rouges au fur et à mesure plutôt que d'attendre l'exécution.

## À retenir

- Python compile le fichier **au complet** avant de l'exécuter : une erreur de syntaxe empêche tout le programme de démarrer.
- Un message d'erreur contient le **fichier**, la **ligne**, un **curseur `^`** et le **type + description**.
- Il faut lire le message **de bas en haut** : d'abord la description, puis la localisation.
- La ligne signalée peut être **celle d'après** la vraie faute : vérifie toujours la ligne précédente.
- Les fautes classiques : `:` oublié, parenthèse ou guillemet non fermé, `=` au lieu de `==`, virgule oubliée, indentation manquante.
- La présence du mot **`Traceback`** indique une erreur d'**exécution**, pas de syntaxe.
