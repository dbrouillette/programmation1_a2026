# Sauvegarder les paramètres d'une application

## Objectifs

- Comprendre le rôle d'un fichier de paramètres (configuration).
- Connaître l'ancêtre : le fichier `.ini`.
- Sauvegarder et recharger des paramètres dans un fichier JSON.
- Prévoir des **valeurs par défaut** pour que l'application fonctionne toujours.
- Choisir où ranger le fichier de paramètres.

> 📋 **Prérequis** : les fiches 9.1 à 9.5, en particulier les dictionnaires en JSON ([9.5](9.5%20-%20Les%20dictionnaires%20en%20JSON.md)).

## 1. Principe

Presque toutes les applications **se souviennent** de tes choix : le thème sombre de VS Code, le volume d'un jeu, la langue d'un logiciel, la taille de la fenêtre… Ces réglages sont des **paramètres** (on dit aussi **configuration** ou **préférences**).

Ils sont sauvegardés dans un petit fichier, lu au démarrage de l'application et réécrit quand l'utilisateur change un réglage.

Les exigences d'un bon fichier de paramètres :

- **lisible et modifiable** par un humain avec un simple éditeur de texte;
- l'application doit **démarrer même si le fichier n'existe pas** (première exécution) ou s'il est **abîmé**;
- l'ajout d'un **nouveau paramètre** dans une nouvelle version de l'application ne doit pas briser les anciens fichiers.

## 2. Un peu d'histoire : les fichiers `.ini`

Dans les années 1990, sous Windows 3.1 et Windows 95, chaque logiciel rangeait ses paramètres dans un fichier **`.ini`** (pour *initialisation*). On en trouve encore partout, par exemple pour les jeux vidéo ou les pilotes d'imprimante :

```ini
; Paramètres du Café Le Binaire
[affichage]
theme = sombre
taille_police = 14

[son]
volume = 7
sons_actifs = oui
```

- les **sections** sont entre crochets `[ ]`;
- chaque ligne est une paire `cle = valeur`;
- les commentaires commencent par `;` ou `#`.

Python sait toujours lire ces fichiers avec le module `configparser` :

```python
import configparser

config = configparser.ConfigParser()
config.read("parametres.ini", encoding="utf-8")

theme = config["affichage"]["theme"]                 # 'sombre'
volume = config["son"].getint("volume")              # 7
sons_actifs = config["son"].getboolean("sons_actifs")  # True
```

Le format `.ini` a cependant des limites : **toutes les valeurs sont des chaînes** (il faut convertir), il n'y a **pas de listes** et pas de données imbriquées, et chaque logiciel l'interprète un peu à sa façon.

## 3. La façon moderne : un fichier JSON

Aujourd'hui, la plupart des applications utilisent **JSON** (voir la fiche [Module json](../Outils/Fichiers%20JSON%20-%20Module%20json.md)). C'est le cas de VS Code : ouvre la palette de commandes (`Ctrl+Maj+P`) et tape *Preferences: Open User Settings (JSON)* pour voir ton propre fichier `settings.json`!

Le même contenu, en JSON :

```json
{
    "theme": "sombre",
    "taille_police": 14,
    "volume": 7,
    "sons_actifs": true,
    "fichiers_recents": ["menu.csv", "ventes_novembre.csv"]
}
```

Avantages : les nombres et les booléens gardent leur type, on peut avoir des listes, et un seul appel à `json.load()` suffit.

> 💡 Tu croiseras aussi le format **TOML** (`.toml`), une version moderne et typée du `.ini`, très utilisée pour configurer les projets Python (`pyproject.toml`). Python sait le **lire** avec le module `tomllib`, mais pas l'écrire. Pour des paramètres que l'application doit **modifier**, JSON reste le choix le plus simple.

## 4. Rappel : un objet JSON est un dictionnaire

Comme on l'a vu en [9.5](9.5%20-%20Les%20dictionnaires%20en%20JSON.md), un objet JSON `{ }` est relu comme un dictionnaire par `json.load()`, avec ses types. C'est ce qui fait de JSON le format idéal pour des paramètres : chaque réglage a un **nom** (la clé), plutôt qu'une position dans une liste.

## 5. Le patron complet

Voici la recette à retenir. Elle tient en trois éléments : un dictionnaire de **valeurs par défaut**, une fonction `charger_parametres()` et une fonction `sauvegarder_parametres()`.

```python
import json
from pathlib import Path

CHEMIN_PARAMETRES = Path(__file__).parent / "parametres.json"

PARAMETRES_DEFAUT = {
    "theme": "clair",
    "taille_police": 12,
    "volume": 5,
    "sons_actifs": True,
    "nom_utilisateur": "",
}

def charger_parametres():
    """Renvoie les paramètres de l'application.

    Part toujours des valeurs par défaut, puis les remplace par celles du fichier,
    si le fichier existe, est valide et contient une valeur du bon type.
    """
    lus = {}
    try:
        with open(CHEMIN_PARAMETRES, "r", encoding="utf-8") as fichier:
            lus = json.load(fichier)
    except FileNotFoundError:
        pass                                    # première exécution : valeurs par défaut
    except json.JSONDecodeError:
        print("Avertissement : fichier de paramètres invalide, valeurs par défaut utilisées.")

    parametres = {}
    for cle in PARAMETRES_DEFAUT:
        defaut = PARAMETRES_DEFAUT[cle]
        valeur = lus.get(cle, defaut)
        if type(valeur) == type(defaut):        # on refuse une valeur du mauvais type
            parametres[cle] = valeur
        else:
            parametres[cle] = defaut
    return parametres

def sauvegarder_parametres(parametres):
    """Écrit les paramètres dans le fichier JSON."""
    with open(CHEMIN_PARAMETRES, "w", encoding="utf-8") as fichier:
        json.dump(parametres, fichier, indent=4, ensure_ascii=False)
```

### Pourquoi partir des valeurs par défaut?

La boucle sur `PARAMETRES_DEFAUT` règle d'un coup tous les cas difficiles :

| Situation | Résultat |
| --- | --- |
| Le fichier n'existe pas | `lus` est vide → toutes les valeurs par défaut |
| Le fichier est invalide (erreur de syntaxe) | Avertissement → toutes les valeurs par défaut |
| Un paramètre manque (ajouté dans une nouvelle version) | `get()` donne la valeur par défaut pour celui-là seulement |
| Un paramètre a le mauvais type (`"volume": "fort"`) | Valeur par défaut pour celui-là seulement |
| Le fichier contient une clé inconnue (ancienne version) | Elle est simplement ignorée |

> 📌 **Règle d'or** : un fichier de paramètres ne doit **jamais** empêcher l'application de démarrer.

> ⚠️ La comparaison `type(valeur) == type(defaut)` est stricte : si la valeur par défaut est `5` (un `int`), un `5.0` dans le fichier sera refusé. Choisis donc bien le type de chaque valeur par défaut.

## 6. Utiliser les paramètres dans le programme

```python
def main():
    parametres = charger_parametres()

    if parametres["nom_utilisateur"] == "":
        parametres["nom_utilisateur"] = input("Bienvenue! Quel est votre nom? ").strip()
        sauvegarder_parametres(parametres)

    print(f"Bonjour {parametres['nom_utilisateur']}!")
    print(f"Thème : {parametres['theme']} | Volume : {parametres['volume']}")

main()
```

Première exécution :

```text
Bienvenue! Quel est votre nom? David
Bonjour David!
Thème : clair | Volume : 5
```

Exécutions suivantes :

```text
Bonjour David!
Thème : clair | Volume : 5
```

> 💡 **Quand sauvegarder?** Le plus sûr est de sauvegarder **dès qu'un paramètre change**. Si on attend la fermeture du programme, un plantage ou une fenêtre fermée avec le ✕ fait perdre les modifications.

Un exemple complet, avec un menu pour modifier chaque paramètre et une validation des saisies, se trouve dans [Exemples/Paramètres JSON](Exemples/Paramètres%20JSON/parametres_app.py).

## 7. Où ranger le fichier de paramètres?

| Emplacement | Exemple | Pour… |
| --- | --- | --- |
| À côté du programme | `Path(__file__).parent / "parametres.json"` | Les travaux du cours, un petit outil personnel |
| Dans le dossier de l'utilisateur | `Path.home() / ".cafe_binaire" / "parametres.json"` | Une vraie application installée |

Pourquoi les vraies applications utilisent-elles le dossier de l'utilisateur?

- Chaque utilisateur de l'ordinateur a **ses propres** préférences.
- Le dossier d'installation d'un logiciel (`C:\Program Files\...`) est souvent **protégé en écriture**.
- Une mise à jour de l'application peut remplacer ses fichiers… mais pas ceux de l'utilisateur.

```python
from pathlib import Path

DOSSIER_APP = Path.home() / ".cafe_binaire"      # C:\Users\david\.cafe_binaire sous Windows
DOSSIER_APP.mkdir(exist_ok=True)                  # crée le dossier s'il n'existe pas
CHEMIN_PARAMETRES = DOSSIER_APP / "parametres.json"
```

- `Path.home()` donne le dossier personnel de l'utilisateur, peu importe le système d'exploitation.
- Le point au début de `.cafe_binaire` est une convention (surtout sous macOS et Linux) pour un dossier **caché**.
- `mkdir(exist_ok=True)` crée le dossier, sans erreur s'il existe déjà.

> 💡 Sous Windows, les applications rangent plutôt leurs paramètres dans `C:\Users\<nom>\AppData\Roaming\<application>`; VS Code, par exemple, y garde son `settings.json`. Pour ce cours, `Path.home()` ou le dossier du programme suffisent amplement.

## 8. Bonnes pratiques

- ✅ Toujours définir des **valeurs par défaut** dans le code.
- ✅ Ne jamais faire planter l'application à cause du fichier de paramètres.
- ✅ Utiliser des noms de clés clairs, en `snake_case`, sans accents.
- ✅ Écrire avec `indent=4` pour que l'utilisateur puisse modifier le fichier à la main.
- ✅ Valider les valeurs lues (type, et au besoin intervalle : un volume entre 0 et 10).
- ❌ Ne jamais sauvegarder un **mot de passe** en clair dans un fichier de paramètres.
- ❌ Ne pas déposer son fichier de paramètres personnels dans Git : on l'ajoute au `.gitignore`.

## En résumé

- Un fichier de paramètres permet à l'application de se souvenir des choix de l'utilisateur.
- Les fichiers `.ini` (lus avec `configparser`) sont l'ancienne façon de faire; toutes leurs valeurs sont des chaînes.
- La façon moderne : un fichier **JSON** lu avec `json.load()` et écrit avec `json.dump()`.
- On part toujours d'un dictionnaire `PARAMETRES_DEFAUT`, qu'on complète avec les valeurs valides du fichier.
- Fichier absent, invalide ou incomplet : l'application démarre quand même.
- Pour un petit programme, le fichier va à côté du programme; pour une vraie application, dans le dossier de l'utilisateur (`Path.home()`).
