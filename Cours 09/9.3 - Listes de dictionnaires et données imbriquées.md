# Listes de dictionnaires et données imbriquées

## Objectifs

- Représenter un tableau de données avec une **liste de dictionnaires**.
- Chercher, filtrer et calculer dans une liste de dictionnaires.
- Combiner dictionnaires et listes : un dictionnaire qui contient une liste.
- Sauvegarder et recharger des dictionnaires en JSON.
- Lire un fichier JSON écrit à la main et **valider** son contenu.

> 🎄 **Fil conducteur** : à la fin de cette fiche, on saura représenter une **chanson complète** du spectacle de Noël (titre, auteur et liste de notes), la lire depuis un fichier `notes.json` écrit à la main et la sauvegarder en JSON.

## 1. Une liste de dictionnaires

Au cours 8, une chanson était une **liste 2D** : chaque rangée `[note, intensite, duree]` était une liste, et il fallait se souvenir que `rangee[2]` était la durée.

Remplaçons chaque rangée par un **dictionnaire** :

```python
chanson = [
    {"note": "MI4", "intensite": 80, "duree": 300},
    {"note": "MI4", "intensite": 80, "duree": 300},
    {"note": "MI4", "intensite": 100, "duree": 600},
    {"note": "SOL4", "intensite": 80, "duree": 300},
]

print(chanson[2])
print(chanson[2]["duree"])
```

```text
{'note': 'MI4', 'intensite': 100, 'duree': 600}
600
```

`chanson[2]` choisit le **troisième** élément de la liste (un dictionnaire), puis `["duree"]` choisit une valeur de ce dictionnaire. On lit de gauche à droite : *la durée de la note no 2*.

| | Liste 2D | Liste de dictionnaires |
| --- | --- | --- |
| Une rangée | `["MI4", 80, 300]` | `{"note": "MI4", "intensite": 80, "duree": 300}` |
| Lire la durée | `rangee[2]` ou `rangee[COL_DUREE]` | `rangee["duree"]` |
| Ajouter une colonne | Décale tous les index… | Ajoute simplement une clé |
| Place en mémoire et dans un fichier | Plus compacte | Plus grande (les clés sont répétées) |

> 📌 La liste de dictionnaires est **la** façon la plus courante de représenter un tableau de données en Python. C'est aussi ce que renvoient la plupart des API Web.

## 2. Parcourir, chercher, calculer

Toutes les recettes sur les listes fonctionnent; seule la façon d'accéder aux colonnes change.

```python
chanson = [
    {"note": "MI4", "intensite": 80, "duree": 300},
    {"note": "MI4", "intensite": 80, "duree": 300},
    {"note": "MI4", "intensite": 100, "duree": 600},
    {"note": "SOL4", "intensite": 80, "duree": 300},
    {"note": "DO4", "intensite": 60, "duree": 450},
]

# Total
duree_totale = 0
for note in chanson:
    duree_totale += note["duree"]
print(f"Durée totale : {duree_totale} ms")

# Filtre
fortes = []
for note in chanson:
    if note["intensite"] >= 100:
        fortes.append(note)
print(f"{len(fortes)} note(s) à pleine intensité")

# Recherche : la première note la plus longue
plus_longue = chanson[0]
for note in chanson:
    if note["duree"] > plus_longue["duree"]:
        plus_longue = note
print(f"Plus longue : {plus_longue['note']} ({plus_longue['duree']} ms)")
```

```text
Durée totale : 1950 ms
1 note(s) à pleine intensité
Plus longue : MI4 (600 ms)
```

## 3. Un dictionnaire qui contient une liste

Une chanson, ce n'est pas seulement des notes : elle a aussi un titre et un auteur (que l'afficheur du sapin devra montrer!). On regroupe le tout dans **un dictionnaire dont une valeur est une liste** :

```python
chanson = {
    "titre": "Au clair de la lune",
    "auteur": "Traditionnel",
    "notes": [
        {"note": "DO4", "intensite": 70, "duree": 400},
        {"note": "DO4", "intensite": 70, "duree": 400},
        {"note": "DO4", "intensite": 70, "duree": 400},
        {"note": "RE4", "intensite": 70, "duree": 400},
        {"note": "MI4", "intensite": 90, "duree": 800},
    ],
}

print(chanson["titre"])
print(len(chanson["notes"]))
print(chanson["notes"][4]["note"])

for note in chanson["notes"]:
    print(note["note"], end=" ")
print()
```

```text
Au clair de la lune
5
MI4
DO4 DO4 DO4 RE4 MI4
```

Pour lire une valeur au fond de la structure, on **enchaîne** les accès, de l'extérieur vers l'intérieur :

```text
chanson["notes"][4]["note"]
   │        │     │     └─ la clé "note" de ce dictionnaire → "MI4"
   │        │     └─ l'élément no 4 de cette liste → un dictionnaire
   │        └─ la valeur de la clé "notes" → une liste
   └─ le dictionnaire de la chanson
```

> 💡 Si tu te perds dans une structure imbriquée, affiche une étape à la fois avec `print()` et `type()` : `print(type(chanson["notes"]))`, puis `print(type(chanson["notes"][4]))`…

### Un dictionnaire de listes

L'inverse existe aussi : un dictionnaire dont **chaque valeur est une liste**. Par exemple, les chansons regroupées par catégorie :

```python
categories = {
    "Classiques": ["Vive le vent", "Au clair de la lune"],
    "Modernes": [],
}

categories["Modernes"].append("Ma chanson")        # ajoute à une liste existante
categories["Douces"] = ["Douce nuit"]              # crée une nouvelle catégorie

for nom, titres in categories.items():
    print(f"{nom} ({len(titres)}) : {', '.join(titres)}")
```

```text
Classiques (2) : Vive le vent, Au clair de la lune
Modernes (1) : Ma chanson
Douces (1) : Douce nuit
```

## 4. Les dictionnaires en JSON

Dans la fiche [Module json](../Outils/Fichiers%20JSON%20-%20Module%20json.md), on a sauvegardé des **listes** en JSON. Les **objets** JSON, entre accolades `{ }`, correspondent exactement aux dictionnaires Python :

| JSON | Python |
| --- | --- |
| tableau `[ ]` | liste |
| objet `{ }` | dictionnaire |

`json.dump()` et `json.load()` fonctionnent sans aucun changement :

```python
import json
from pathlib import Path

CHEMIN_CHANSON = Path(__file__).parent / "au_clair_de_la_lune.json"

chanson = {
    "titre": "Au clair de la lune",
    "auteur": "Traditionnel",
    "notes": [
        {"note": "DO4", "intensite": 70, "duree": 400},
        {"note": "RE4", "intensite": 70, "duree": 400},
        {"note": "MI4", "intensite": 90, "duree": 800},
    ],
}

with open(CHEMIN_CHANSON, "w", encoding="utf-8") as fichier:
    json.dump(chanson, fichier, indent=4, ensure_ascii=False)

with open(CHEMIN_CHANSON, "r", encoding="utf-8") as fichier:
    relue = json.load(fichier)

print(relue["notes"][2]["duree"] + 100)
```

```text
900
```

Le fichier `au_clair_de_la_lune.json` produit :

```json
{
    "titre": "Au clair de la lune",
    "auteur": "Traditionnel",
    "notes": [
        {
            "note": "DO4",
            "intensite": 70,
            "duree": 400
        },
        ...
    ]
}
```

Les clés rendent le fichier **lisible et modifiable** par un humain : on sait tout de suite ce que représente chaque nombre.

> ⚠️ En JSON, les clés d'un objet sont **toujours des chaînes**. Un dictionnaire Python dont les clés sont des nombres (`{1234: "Labo"}`) sera relu avec des clés chaînes (`{"1234": "Labo"}`). Pour éviter les surprises, on utilise des clés chaînes dans les données qu'on sauvegarde.

## 5. Lire un fichier JSON écrit à la main

Les données d'un programme sont souvent **écrites à la main** dans VS Code, directement en JSON. Pour une chanson, une ligne par note reste compacte et lisible :

```json
[
    {"note": "MI4", "intensite": 80, "duree": 300},
    {"note": "MI4", "intensite": 80, "duree": 300},
    {"note": "MI4", "intensite": 100, "duree": 600},
    {"note": "SOL4", "intensite": 80, "duree": 300}
]
```

> ⚠️ Rappels de syntaxe JSON : guillemets **doubles** seulement, une virgule entre les éléments, mais **aucune** virgule après le dernier. VS Code souligne en rouge ces erreurs dans un fichier `.json`.

`json.load()` relit ce fichier en une ligne, avec les bons types : `"intensite"` et `"duree"` sont déjà des `int`.

### Valider ce qu'on a lu

Un fichier écrit à la main contient tôt ou tard une erreur. `json.load()` détecte les erreurs de **syntaxe** (`json.JSONDecodeError`), mais pas les erreurs de **contenu** : une clé oubliée, une intensité écrite `"fort"` au lieu d'un nombre, une durée négative… Ces erreurs-là, c'est à nous de les détecter, **une seule fois**, au chargement :

```python
import json
from pathlib import Path

CHEMIN_NOTES = Path(__file__).parent / "notes.json"
CLES = ["note", "intensite", "duree"]


def note_valide(element):
    """Renvoie True si l'élément est une note bien formée."""
    if type(element) != dict:
        return False
    for cle in CLES:
        if cle not in element:
            return False
    return (type(element["note"]) == str
            and type(element["intensite"]) == int
            and type(element["duree"]) == int
            and 0 <= element["intensite"] <= 100
            and element["duree"] > 0)


def charger_notes(chemin):
    """Renvoie la liste des notes valides du fichier, ou une liste vide en cas de problème."""
    try:
        with open(chemin, "r", encoding="utf-8") as fichier:
            donnees = json.load(fichier)
    except FileNotFoundError:
        print(f"Le fichier {chemin.name} est introuvable.")
        return []
    except json.JSONDecodeError:
        print(f"Le fichier {chemin.name} contient une erreur de syntaxe JSON.")
        return []

    if type(donnees) != list:
        print(f"Le fichier {chemin.name} doit contenir une liste de notes.")
        return []

    notes = []
    for i in range(len(donnees)):
        if note_valide(donnees[i]):
            notes.append(donnees[i])
        else:
            print(f"Note no {i + 1} ignorée : {donnees[i]}")
    return notes


notes = charger_notes(CHEMIN_NOTES)
print(f"{len(notes)} notes valides.")
```

| Problème dans le fichier | Qui le détecte? |
| --- | --- |
| Virgule de trop, guillemet simple, crochet oublié | `json.load()` → `json.JSONDecodeError` |
| Le fichier contient autre chose qu'une liste | Nous : `type(donnees) != list` |
| Une clé manquante (`"duree"` oubliée) | Nous : `cle not in element` |
| Un mauvais type (`"intensite": "fort"`) | Nous : `type(...) == int` |
| Une valeur hors limites (`"intensite": 120`) | Nous : `0 <= ... <= 100` |

> 💡 Comparé au CSV, il n'y a plus de `strip()`, de `split()` ni de `int()` : les données arrivent déjà structurées et typées. Il reste seulement à vérifier qu'elles ont **la bonne forme**.

## 6. Bonnes pratiques avec les structures imbriquées

- ✅ Garder la **même forme** pour tous les éléments d'une liste : chaque note a les clés `note`, `intensite` et `duree`, ni plus, ni moins.
- ✅ Écrire de petites fonctions qui **cachent la structure** : `calculer_duree_totale(chanson)` est plus lisible que trois niveaux de crochets dans le programme principal.
- ✅ Valider les données lues d'un fichier (clés présentes, types, intervalles) **une seule fois**, au chargement.
- ❌ Éviter plus de trois niveaux d'imbrication : au-delà, la structure devient difficile à suivre.

## En résumé

- Une **liste de dictionnaires** représente un tableau de données : `chanson[2]["duree"]`.
- Les recettes sur les listes (total, filtre, recherche) fonctionnent : on accède aux colonnes par leur nom.
- Un dictionnaire peut contenir une liste (`chanson["notes"]`), et inversement.
- On lit une structure imbriquée en enchaînant les accès, de l'extérieur vers l'intérieur.
- Les objets JSON `{ }` correspondent aux dictionnaires : `json.dump()` et `json.load()` fonctionnent sans changement.
- Un fichier JSON écrit à la main se relit avec `json.load()`, puis se **valide** : type de la structure, clés présentes, types et limites des valeurs.
