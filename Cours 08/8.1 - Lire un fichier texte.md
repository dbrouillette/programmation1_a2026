# Lire un fichier texte

## Objectifs

- Comprendre pourquoi un programme a besoin de fichiers.
- Ouvrir un fichier avec `open()` et le refermer automatiquement avec `with`.
- Choisir le bon **mode** d'ouverture.
- Comprendre ce qu'est un **encodage** (ASCII, cp1252, UTF-8) et reconnaître un problème d'encodage.
- Lire un fichier en entier, ligne par ligne ou dans une liste.
- Nettoyer les lignes lues avec `strip()`.
- Gérer l'erreur `FileNotFoundError`.
- Localiser un fichier de façon fiable, peu importe d'où le programme est lancé.

> ⚠️ **Python Tutor ne gère pas les fichiers.** Les exemples de ce cours doivent être exécutés dans VS Code. Crée les fichiers texte (`.txt`, `.csv`, `.json`) dans le **même dossier** que ton programme.

## 1. Principe

Jusqu'ici, toutes les données de nos programmes vivaient dans des **variables**, donc dans la mémoire vive (RAM). Dès que le programme se termine, tout disparaît : la commande du client, le score du joueur, la liste d'épicerie…

Un **fichier** est stocké sur le disque. Il survit à la fermeture du programme et même à l'arrêt de l'ordinateur. On s'en sert pour :

- **lire** des données préparées à l'avance (un menu, une liste de questions, une chanson);
- **sauvegarder** des résultats (un historique de ventes, un tableau des meilleurs scores);
- **mémoriser** les préférences de l'utilisateur d'une exécution à l'autre (nous le verrons au cours 9).

Travailler avec un fichier se fait toujours en trois étapes :

1. **Ouvrir** le fichier;
2. **Lire** ou **écrire**;
3. **Fermer** le fichier.

## 2. Ouvrir un fichier : `open()`

```python
fichier = open("menu.txt", "r", encoding="utf-8")
contenu = fichier.read()
fichier.close()
```

La fonction `open()` reçoit trois informations :

| Argument | Rôle | Exemple |
| --- | --- | --- |
| Le **chemin** du fichier | Où trouver le fichier | `"menu.txt"` |
| Le **mode** | Ce qu'on veut faire avec le fichier | `"r"` pour lire |
| L'**encodage** | Comment les caractères sont codés en octets | `encoding="utf-8"` |

### Les modes d'ouverture

| Mode | Signification | Si le fichier n'existe pas | Si le fichier existe |
| --- | --- | --- | --- |
| `"r"` | *read* : lecture (mode par défaut) | ❌ `FileNotFoundError` | On lit son contenu |
| `"w"` | *write* : écriture | Il est créé | ⚠️ Son contenu est **effacé** |
| `"a"` | *append* : ajout à la fin | Il est créé | On écrit à la suite |

Les modes `"w"` et `"a"` sont présentés en [8.2](8.2%20-%20Écrire%20dans%20un%20fichier%20texte.md).

### C'est quoi, l'encodage?

Un ordinateur ne connaît que des **nombres**. Sur le disque, un fichier texte n'est qu'une suite d'**octets**, des nombres entre 0 et 255. Il n'y a pas de lettres dedans!

Pour stocker du texte, il faut donc une **table de correspondance** entre les caractères et les nombres. Cette table, c'est l'**encodage**. Pense à un code secret : pour relire un message, il faut utiliser **le même code** que celui qui l'a écrit.

#### ASCII : l'ancêtre (années 1960)

La table **ASCII** associe un nombre de 0 à 127 à chaque lettre de l'alphabet anglais, chaque chiffre et chaque symbole courant. Par exemple, `A` vaut 65, `B` vaut 66 et `a` vaut 97. La fonction `ord()` de Python donne ce nombre :

```python
print(ord("A"))    # 65
print(ord("a"))    # 97
```

Problème : ASCII a été conçu aux États-Unis. Il n'y a **aucune lettre accentuée** : ni `é`, ni `è`, ni `ç`.

#### Les tables régionales : le chaos

Pour ajouter les accents, chaque région a utilisé les nombres libres (128 à 255) **à sa façon**. Windows, en Europe de l'Ouest et en Amérique, utilise la table **cp1252** (aussi appelée *Windows-1252*), où `é` vaut 233. Mais en Russie, le même nombre 233 donne une lettre cyrillique, et en Grèce, une lettre grecque!

Un même fichier pouvait donc s'afficher différemment selon l'ordinateur qui l'ouvrait.

#### UTF-8 : une seule table pour toute la planète

**Unicode** est une table unique qui donne un numéro à **chaque caractère de toutes les langues du monde** : le français, le chinois, l'arabe, les symboles mathématiques… et même les émojis. **UTF-8** est la façon la plus répandue d'écrire ces numéros en octets :

| Caractère | Octets en UTF-8 | Nombre d'octets |
| --- | --- | --- |
| `A` | 65 | 1 (identique à ASCII) |
| `é` | 195 169 | 2 |
| `€` | 226 130 172 | 3 |
| `😀` | 240 159 152 128 | 4 |

Les lettres anglaises prennent 1 octet, exactement comme en ASCII. Les autres caractères en prennent de 2 à 4. UTF-8 est aujourd'hui utilisé par plus de 98 % des sites Web : c'est **la** norme.

> 💡 La méthode `encode()` montre les octets qui représentent une chaîne : `"é".encode("utf-8")` donne `b'\xc3\xa9'`, soit les octets 195 et 169 écrits en hexadécimal.

#### Quand le code ne correspond pas : le « charabia »

Si on écrit un fichier en UTF-8 et qu'on le relit avec une autre table, chaque octet est traduit séparément. Le `è` de `Trois-Rivières` est écrit avec 2 octets (195 168). Relus avec la table cp1252, ces 2 octets deviennent **2 caractères** : `Ã` et `¨`.

```text
Écrit en UTF-8, relu en cp1252  →  Trois-RiviÃ¨res
```

Si tu vois des `Ã©`, `Ã¨` ou `Ã§` dans un texte, c'est presque toujours un fichier UTF-8 relu avec le mauvais encodage.

L'inverse provoque carrément une erreur. Un fichier écrit en cp1252 contient des octets qui n'ont pas de sens en UTF-8 :

```text
UnicodeDecodeError: 'utf-8' codec can't decode byte 0xe8 in position 10: invalid continuation byte
```

Ici, `0xe8` (232) est le `è` de cp1252. Python refuse de deviner et lève une erreur.

> 💡 Le fichier n'est pas abîmé : ses octets sont intacts. C'est seulement la **lecture** qui utilise la mauvaise table. On règle le problème en rouvrant le fichier avec le bon encodage.

### Toujours préciser l'encodage

Sans le paramètre `encoding`, Python utilise l'encodage **par défaut de l'ordinateur**. Sous Windows, c'est souvent cp1252, alors que macOS et Linux utilisent UTF-8. Un programme qui fonctionne chez toi peut donc afficher du charabia chez ton professeur.

```python
# ❌ Mauvais : l'encodage par défaut dépend de l'ordinateur (souvent cp1252 sous Windows)
fichier = open("menu.txt", "r")

# ✅ Bon : UTF-8 est la norme actuelle, partout
fichier = open("menu.txt", "r", encoding="utf-8")
```

> 📌 **Règle pratique** : on écrit **toujours** `encoding="utf-8"` en ouvrant un fichier texte.

#### Voir et changer l'encodage dans VS Code

VS Code enregistre les fichiers en UTF-8 par défaut. L'encodage du fichier ouvert est affiché dans la **barre d'état**, en bas à droite (`UTF-8`). En cliquant dessus, on peut :

- **Rouvrir avec l'encodage** (*Reopen with Encoding*) : relire le fichier avec une autre table, par exemple `Western (Windows 1252)`, si les accents sont illisibles;
- **Enregistrer avec l'encodage** (*Save with Encoding*) : convertir le fichier, par exemple en `UTF-8`.

> 💡 Un fichier reçu d'ailleurs (exporté d'Excel, téléchargé d'un vieux site) affiche des `Ã©` ou fait planter ton programme avec `UnicodeDecodeError`? Rouvre-le dans VS Code avec `Windows 1252`, vérifie que les accents sont corrects, puis enregistre-le en `UTF-8`.

## 3. Fermer automatiquement : `with`

Oublier `close()` est une erreur fréquente : le fichier reste verrouillé, et des données écrites peuvent même être perdues. Pire, si une erreur survient entre `open()` et `close()`, la ligne `close()` n'est jamais atteinte.

L'instruction `with` règle le problème : le fichier est **fermé automatiquement** à la fin du bloc indenté, même en cas d'erreur.

```python
with open("menu.txt", "r", encoding="utf-8") as fichier:
    contenu = fichier.read()

# Ici, le fichier est déjà fermé, mais la variable contenu existe toujours.
print(contenu)
```

> 📌 **Règle pratique** : à partir de maintenant, on ouvre **toujours** un fichier avec `with`. On ne verra plus `close()` dans ce cours.

## 4. Lire le contenu

Pour les exemples suivants, crée le fichier `menu.txt` dans le dossier de ton programme :

```text
Café filtre
Latté
Chocolat chaud
Muffin
Biscuit
```

### Lire tout le fichier d'un coup : `read()`

```python
with open("menu.txt", "r", encoding="utf-8") as fichier:
    contenu = fichier.read()

print(contenu)
print(type(contenu))
```

```text
Café filtre
Latté
Chocolat chaud
Muffin
Biscuit

<class 'str'>
```

`read()` renvoie **une seule chaîne** qui contient tout le fichier, y compris les retours de ligne `\n`.

### Lire ligne par ligne avec une boucle `for`

Un fichier ouvert se parcourt comme une liste : chaque tour de boucle donne **une ligne**.

```python
with open("menu.txt", "r", encoding="utf-8") as fichier:
    for ligne in fichier:
        print(ligne)
```

```text
Café filtre

Latté

Chocolat chaud

...
```

Pourquoi une ligne vide entre chaque produit? Parce que chaque ligne lue **se termine par `\n`**, et que `print()` ajoute son propre retour de ligne. On obtient deux retours de ligne.

### Nettoyer les lignes : `strip()`

La méthode `strip()` (voir [Manipulations de chaînes](../Outils/Manipulations%20de%20chaînes.md)) enlève les espaces et les `\n` au début et à la fin d'une chaîne :

```python
with open("menu.txt", "r", encoding="utf-8") as fichier:
    for ligne in fichier:
        produit = ligne.strip()
        print(f"- {produit}")
```

```text
- Café filtre
- Latté
- Chocolat chaud
- Muffin
- Biscuit
```

> 📌 **Règle pratique** : une ligne lue dans un fichier passe presque toujours par `strip()` avant d'être utilisée.

### Charger les lignes dans une liste

On combine la boucle `for` et `append()` vus en [6.2 - Les listes](../Cours%2006/6.2%20-%20Les%20listes.md) :

```python
produits = []
with open("menu.txt", "r", encoding="utf-8") as fichier:
    for ligne in fichier:
        produit = ligne.strip()
        if produit != "":          # on ignore les lignes vides
            produits.append(produit)

print(produits)
print(f"{len(produits)} produits au menu.")
```

```text
['Café filtre', 'Latté', 'Chocolat chaud', 'Muffin', 'Biscuit']
5 produits au menu.
```

> 💡 Ignorer les lignes vides rend le programme plus robuste : une ligne vide oubliée à la fin du fichier ne crée pas un produit `""`.

### Lire des nombres

Tout ce qu'on lit dans un fichier texte est une **chaîne**, exactement comme avec `input()`. Pour faire des calculs, il faut convertir avec `int()` ou `float()`.

Fichier `ventes_jour.txt` :

```text
12.50
8.75
23.10
4.50
```

```python
total = 0.0
with open("ventes_jour.txt", "r", encoding="utf-8") as fichier:
    for ligne in fichier:
        total += float(ligne)

print(f"Ventes du jour : {total:.2f} $")
```

```text
Ventes du jour : 48.85 $
```

> 💡 `float()` et `int()` tolèrent les espaces et le `\n` autour du nombre : `float("12.50\n")` fonctionne. Un `strip()` ne nuit pas pour autant.

## 5. Le fichier n'existe pas : `FileNotFoundError`

Si le fichier est introuvable, `open()` lève une exception :

```text
FileNotFoundError: [Errno 2] No such file or directory: 'menu.txt'
```

On la gère avec `try` / `except`, comme en [5.2 - La gestion des erreurs](../Cours%2005/5.2%20-%20La%20gestion%20des%20erreurs.md) :

```python
def lire_produits(nom_fichier):
    """Renvoie la liste des produits du fichier, ou une liste vide s'il est introuvable."""
    produits = []
    try:
        with open(nom_fichier, "r", encoding="utf-8") as fichier:
            for ligne in fichier:
                produit = ligne.strip()
                if produit != "":
                    produits.append(produit)
    except FileNotFoundError:
        print(f"Avertissement : le fichier {nom_fichier} est introuvable.")
    return produits


menu = lire_produits("menu.txt")
```

> 📌 Une fonction `lire_...()` qui **renvoie** les données lues, comme en [7.4](../Cours%2007/7.4%20-%20Renvoyer%20une%20valeur.md), est le modèle à suivre : le reste du programme ne sait même pas que les données viennent d'un fichier.

## 6. Où Python cherche-t-il le fichier?

Un chemin comme `"menu.txt"` est un **chemin relatif** : Python le cherche dans le **dossier courant** (*current working directory*), c'est-à-dire le dossier **depuis lequel le programme est lancé**… qui n'est pas toujours celui du fichier `.py`!

C'est le piège classique dans VS Code : si tu as ouvert le dossier `programmation1_a2026` au complet et que ton programme est dans `Cours 08/Exemples`, le dossier courant est souvent `programmation1_a2026`. Résultat : `FileNotFoundError`, alors que `menu.txt` est juste à côté du programme.

### La solution : partir du dossier du programme

Le module `pathlib` permet de construire un chemin à partir du dossier qui contient le fichier `.py` :

```python
from pathlib import Path

DOSSIER = Path(__file__).parent          # dossier qui contient ce programme
CHEMIN_MENU = DOSSIER / "menu.txt"       # l'opérateur / assemble les morceaux du chemin

with open(CHEMIN_MENU, "r", encoding="utf-8") as fichier:
    contenu = fichier.read()
```

- `__file__` est une variable spéciale qui contient le chemin du programme en cours d'exécution.
- `.parent` donne le dossier qui le contient.
- L'opérateur `/` assemble un dossier et un nom de fichier, avec le bon séparateur (`\` sous Windows, `/` sous macOS et Linux).

> 📌 **Règle pratique** : dans un programme qui sera remis ou partagé, on construit les chemins avec `Path(__file__).parent`. Le programme fonctionne alors peu importe d'où il est lancé.

### Chemins absolus

Un **chemin absolu** part de la racine du disque, par exemple `C:\Users\david\Documents\menu.txt`. On l'évite dans un programme : il ne fonctionnera pas sur l'ordinateur de quelqu'un d'autre.

> ⚠️ Si tu dois quand même écrire un chemin Windows dans une chaîne, attention aux `\` : `"C:\nouveau"` contient un `\n` (retour de ligne)! Utilise plutôt des `/`, que Windows accepte aussi : `"C:/Users/david/menu.txt"`.

## En résumé

- Un fichier conserve les données **après** la fin du programme.
- On ouvre un fichier avec `with open(chemin, mode, encoding="utf-8") as fichier:`; il est fermé automatiquement à la fin du bloc.
- Le mode `"r"` sert à lire; c'est le mode par défaut.
- L'**encodage** est la table qui traduit les octets du fichier en caractères. UTF-8 couvre toutes les langues; des `Ã©` signalent un fichier relu avec la mauvaise table.
- `fichier.read()` renvoie tout le contenu dans une seule chaîne; `for ligne in fichier:` parcourt les lignes une à une.
- Chaque ligne lue se termine par `\n` : on la nettoie avec `strip()`.
- Tout ce qu'on lit est une **chaîne** : il faut convertir avec `int()` ou `float()` pour calculer.
- Un fichier introuvable lève `FileNotFoundError`, qu'on gère avec `try` / `except`.
- `Path(__file__).parent / "fichier.txt"` construit un chemin fiable vers un fichier placé à côté du programme.
