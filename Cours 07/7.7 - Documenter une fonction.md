# Documenter une fonction

## Objectifs

- Comprendre l'utilité d'une **docstring** et la distinguer d'un commentaire.
- Rédiger une docstring d'une ligne et une docstring complète (format Google).
- Générer automatiquement un patron de docstring dans VS Code avec l'extension **autoDocstring**.
- Consulter la documentation d'une fonction dans VS Code et avec `help()`.

## 1. Principe

Lorsqu'on appelle `round()` ou `len()`, on n'a jamais besoin de lire leur code : il suffit de savoir **ce qu'elles font**, **ce qu'il faut leur donner** et **ce qu'elles renvoient**. Ces informations se trouvent dans leur **documentation**.

Nos fonctions méritent la même chose. Une **docstring** (*documentation string*) est une chaîne de caractères placée **juste sous la ligne `def`**, entre triples guillemets `"""`, qui décrit la fonction.

```python
def calculer_taxes(montant):
    """Calcule la TPS et la TVQ sur un montant, arrondies au cent."""
    tps = round(montant * TAUX_TPS, 2)
    tvq = round(montant * TAUX_TVQ, 2)
    return tps, tvq
```

### Docstring ou commentaire?

| | Commentaire `#` | Docstring `"""` |
| --- | --- | --- |
| S'adresse à… | celui qui **lit le code** de la fonction | celui qui **utilise** la fonction |
| Explique… | **comment** le code fonctionne | **ce que fait** la fonction et **comment l'appeler** |
| Position | n'importe où | première ligne du corps de la fonction |
| Affichée par VS Code et `help()` | ❌ Non | ✅ Oui |

## 2. La docstring d'une ligne

Pour une fonction simple, une seule phrase suffit. Elle décrit **ce que fait** la fonction, commence par un verbe et se termine par un point.

```python
def afficher_entete():
    """Affiche le nom du café encadré de deux lignes."""
    afficher_separateur("=")
    print(f"{NOM_CAFE:^{LARGEUR_FACTURE}}")
    afficher_separateur("=")
```

Les triples guillemets ouvrants et fermants sont sur la **même ligne** que le texte.

## 3. La docstring complète (format Google)

Dès qu'une fonction a des paramètres ou renvoie une valeur, la docstring doit les décrire. Il existe plusieurs formats; dans ce cours, on utilise le **format Google**, simple à lire et très répandu.

```python
def calculer_total(sous_total, rabais=0.0, pourboire=0.0):
    """Calcule le total à payer.

    Args:
        sous_total (float): Le sous-total de la commande.
        rabais (float, optional): Le taux du rabais. Par défaut 0.0.
        pourboire (float, optional): Le pourboire, en dollars. Par défaut 0.0.

    Returns:
        float: Le total, rabais, taxes et pourboire inclus.
    """
    montant = sous_total - calculer_rabais(sous_total, rabais)
    tps, tvq = calculer_taxes(montant)
    return round(montant + tps + tvq + pourboire, 2)
```

| Partie | Contenu |
| --- | --- |
| **Résumé** | Une phrase qui dit ce que fait la fonction, suivie d'une ligne vide. |
| **`Args:`** | Un paramètre par ligne : `nom (type): description.` On ajoute `optional` si le paramètre a une valeur par défaut, et on précise cette valeur. |
| **`Returns:`** | Le type et la description de la valeur renvoyée. On omet cette section si la fonction ne renvoie rien. |

> 💡 Les mots-clés `Args:` et `Returns:` restent en anglais : ce sont des marqueurs reconnus par les outils, comme VS Code. Les descriptions, elles, s'écrivent en français.

Les types les plus courants à indiquer sont ceux qu'on connaît déjà : `int`, `float`, `str`, `bool`, `list` et `tuple`.

### Une fonction qui ne renvoie rien

Pour une fonction qui affiche ou qui modifie une liste, il n'y a pas de section `Returns:`. On peut préciser l'effet de la fonction dans le résumé :

```python
def ajouter_au_panier(quantites, index, quantite):
    """Ajoute une quantité d'un produit au panier.

    La liste quantites est modifiée directement : rien n'est retourné.

    Args:
        quantites (list): Les quantités commandées, une par produit.
        index (int): L'index du produit dans PRODUITS.
        quantite (int): La quantité à ajouter.
    """
    quantites[index] += quantite
```

## 4. Le truc : coder d'abord, documenter ensuite

Écrire une docstring complète à la main est fastidieux… et il est facile d'oublier un paramètre. La bonne méthode :

1. **Écrire et tester le code de la fonction** d'abord. À ce moment, on sait exactement quels paramètres elle reçoit et ce qu'elle renvoie.
2. **Générer le patron** de la docstring automatiquement.
3. **Remplir les trous** du patron.

### Installer l'extension autoDocstring (une seule fois)

1. Dans VS Code, ouvrir l'onglet **Extensions** (`Ctrl + Maj + X`).
2. Rechercher **autoDocstring** (*autoDocstring - Python Docstring Generator*, par Nils Werner).
3. Cliquer sur **Installer**.

Le format Google est le format par défaut de l'extension : aucune configuration n'est nécessaire.

### Générer le patron

Prenons la fonction `lire_entier()`, déjà écrite et testée :

```python
def lire_entier(message, minimum=0, maximum=99):
    valide = False
    while not valide:
        ...
    return valeur
```

1. Placer le curseur **au début de la ligne qui suit** `def lire_entier(...)`, et insérer une ligne vide au besoin.
2. Taper `"""` puis appuyer sur `Entrée`.
   - Ou utiliser le raccourci **`Ctrl + Maj + 2`**.
   - Ou ouvrir la palette de commandes (`Ctrl + Maj + P`) et choisir **Generate Docstring**.

L'extension lit la ligne `def` et le corps de la fonction, puis génère un patron de ce genre :

```python
def lire_entier(message, minimum=0, maximum=99):
    """_summary_

    Args:
        message (_type_): _description_
        minimum (int, optional): _description_. Defaults to 0.
        maximum (int, optional): _description_. Defaults to 99.

    Returns:
        _type_: _description_
    """
    valide = False
    ...
```

Remarque tout ce que l'extension a trouvé d'elle-même :

- les **trois paramètres**, dans l'ordre;
- le fait que `minimum` et `maximum` sont **optionnels**, avec leur **valeur par défaut** et leur **type** (deviné à partir de la valeur par défaut);
- la section **`Returns:`**, parce que la fonction contient un `return`.

### Remplir les trous

Les champs à compléter (`_summary_`, `_type_`, `_description_`) sont surlignés. La touche **`Tab`** fait passer au champ suivant, et `Maj + Tab` revient au précédent.

```python
def lire_entier(message, minimum=0, maximum=99):
    """Demande un nombre entier jusqu'à ce que la saisie soit valide.

    Args:
        message (str): Le message affiché à l'utilisateur.
        minimum (int, optional): La plus petite valeur acceptée. Par défaut 0.
        maximum (int, optional): La plus grande valeur acceptée. Par défaut 99.

    Returns:
        int: L'entier saisi, compris entre minimum et maximum.
    """
```

> ⚠️ C'est pour cette raison qu'on documente **après** avoir écrit le code : si la ligne `def` ou le `return` n'existent pas encore, l'extension ne peut pas générer un patron complet.

> 💡 Si la fonction change (un paramètre ajouté, retiré ou renommé), il faut **mettre la docstring à jour**. Une documentation fausse est pire que pas de documentation du tout.

## 5. Consulter la documentation

Une fois la docstring écrite, elle apparaît automatiquement là où on en a besoin :

- **Au survol** : placer la souris sur le nom de la fonction, n'importe où dans le fichier, affiche sa ligne `def` et sa docstring.
- **Pendant la saisie d'un appel** : en tapant `lire_entier(`, VS Code affiche les paramètres attendus et met en évidence celui qu'on est en train d'écrire. Le raccourci `Ctrl + Maj + Espace` réaffiche cette aide.
- **Avec la fonction `help()`** : dans un programme ou dans le terminal interactif de Python, `help(lire_entier)` affiche la docstring.

```python
help(calculer_taxes)
```

```text
Help on function calculer_taxes in module __main__:

calculer_taxes(montant)
    Calcule la TPS et la TVQ sur un montant, arrondies au cent.
```

> 💡 C'est exactement ce que fait VS Code quand on survole `print` ou `round` : il affiche la docstring écrite par les développeurs de Python.

## 6. Bonnes pratiques

### Décrire ce que fait la fonction, pas comment

```python
# ❌ Mauvais : décrit le code ligne par ligne
def calculer_sous_total(quantites):
    """Crée une variable à 0.0, fait une boucle for sur les index et additionne."""
```

```python
# ✅ Bon : décrit le résultat
def calculer_sous_total(quantites):
    """Calcule le sous-total d'une commande, avant rabais et taxes."""
```

### Ne pas simplement répéter le nom

```python
# ❌ Mauvais : n'apprend rien de plus que le nom
def calculer_taxes(montant):
    """Calcule les taxes."""
```

```python
# ✅ Bon : précise quelles taxes et ce qu'on obtient
def calculer_taxes(montant):
    """Calcule la TPS et la TVQ sur un montant, arrondies au cent."""
```

### Documenter aussi le fichier

Une docstring peut aussi être placée **tout en haut d'un fichier** `.py` pour décrire le programme. On y reviendra en [7.8 - Structurer un programme avec des fonctions](7.8%20-%20Structurer%20un%20programme%20avec%20des%20fonctions.md).

## En résumé

- Une **docstring** est une chaîne entre `"""` placée juste sous la ligne `def`; elle décrit **ce que fait** la fonction et **comment l'utiliser**.
- Fonction simple : une ligne. Fonction avec paramètres ou valeur de retour : format Google avec `Args:` et `Returns:`.
- **Coder d'abord, documenter ensuite** : avec l'extension autoDocstring, `"""` + `Entrée` (ou `Ctrl + Maj + 2`) génère le patron, et `Tab` passe d'un champ à l'autre.
- La docstring s'affiche au survol dans VS Code, pendant la saisie d'un appel, et avec `help()`.
- Une docstring doit être tenue à jour lorsque la fonction change.
