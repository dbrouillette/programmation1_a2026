# Structurer un programme avec des fonctions

## Objectifs

- Organiser un programme Python selon une structure type.
- Regrouper le code du programme principal dans une fonction `main()`.
- Suivre le déroulement de l'exécution d'un programme complet.
- Déplacer des fonctions réutilisables dans un deuxième fichier (un **module**) et les importer.
- Comprendre le rôle de `if __name__ == "__main__":`.

## 1. Principe

Avec les fonctions, un programme devient un assemblage de petites pièces. Encore faut-il les ranger dans un ordre logique, pour qu'on s'y retrouve, et pour que chaque fonction soit définie **avant** d'être appelée (voir [7.2](7.2%20-%20Définir%20et%20appeler%20une%20fonction.md)).

Cette fiche présente deux modèles de programme type :

- le **modèle à 1 fichier**, pour un programme simple;
- le **modèle à 2 fichiers**, où les fonctions réutilisables sont placées dans un fichier séparé.

Le programme complet de la caisse du Café Le Binaire est fourni dans les deux versions, dans le dossier [Exemples](Exemples/).

## 2. Le modèle à 1 fichier

Un fichier Python bien structuré contient, **dans cet ordre** :

```text
┌──────────────────────────────────────────────┐
│ 1. Docstring du fichier                      │  Ce que fait le programme
├──────────────────────────────────────────────┤
│ 2. Imports                                   │  import math, import random...
├──────────────────────────────────────────────┤
│ 3. Constantes                                │  TAUX_TPS = 0.05 ...
├──────────────────────────────────────────────┤
│ 4. Fonctions                                 │  def lire_entier(...): ...
│                                              │  def calculer_taxes(...): ...
├──────────────────────────────────────────────┤
│ 5. Fonction main()                           │  Le programme principal
├──────────────────────────────────────────────┤
│ 6. Appel de main()                           │  main()
└──────────────────────────────────────────────┘
```

### Le programme de la caisse

Voici la structure de [caisse.py](Exemples/1%20fichier/caisse.py). Le corps des fonctions, vu dans les fiches précédentes, est remplacé par `...` pour faire ressortir l'organisation :

```python
"""Caisse du Café Le Binaire.

Prend la commande d'un client, puis affiche sa facture avec le rabais
étudiant, les taxes et le pourboire.
"""

# ---------------------------------------------------------------------------
# Constantes
# ---------------------------------------------------------------------------
NOM_CAFE = "Café Le Binaire"
PRODUITS = ("Café filtre", "Latté", "Chocolat chaud", "Muffin", "Biscuit")
PRIX = (2.25, 4.50, 3.75, 3.25, 1.95)
QUANTITE_MAX = 20
TAUX_TPS = 0.05
TAUX_TVQ = 0.09975
RABAIS_ETUDIANT = 0.10


# ---------------------------------------------------------------------------
# Fonctions de saisie
# ---------------------------------------------------------------------------
def lire_entier(message, minimum=0, maximum=99): ...
def lire_reel(message, minimum=0.0): ...
def lire_oui_non(message): ...


# ---------------------------------------------------------------------------
# Fonctions d'affichage
# ---------------------------------------------------------------------------
def afficher_separateur(caractere): ...
def afficher_entete(): ...
def afficher_menu(): ...
def afficher_ligne(produit, quantite, prix_unitaire): ...
def afficher_montant(libelle, montant): ...


# ---------------------------------------------------------------------------
# Fonctions de calcul
# ---------------------------------------------------------------------------
def ajouter_au_panier(quantites, index, quantite): ...
def calculer_sous_total(quantites): ...
def calculer_rabais(montant, taux): ...
def calculer_taxes(montant): ...
def calculer_total(sous_total, rabais=0.0, pourboire=0.0): ...


# ---------------------------------------------------------------------------
# Facture
# ---------------------------------------------------------------------------
def afficher_facture(quantites, rabais=0.0, pourboire=0.0): ...


# ---------------------------------------------------------------------------
# Programme principal
# ---------------------------------------------------------------------------
def main():
    """Prend la commande d'un client, puis affiche sa facture."""
    quantites = [0] * len(PRODUITS)

    afficher_menu()
    choix = lire_entier("Votre choix : ", 0, len(PRODUITS))
    while choix != 0:
        quantite = lire_entier("Quantité : ", 1, QUANTITE_MAX)
        ajouter_au_panier(quantites, choix - 1, quantite)
        choix = lire_entier("Votre choix : ", 0, len(PRODUITS))

    if sum(quantites) == 0:
        print("Aucun produit commandé. À la prochaine!")
    else:
        est_etudiant = lire_oui_non("Carte étudiante? (o/n) : ")
        rabais = RABAIS_ETUDIANT if est_etudiant else 0.0
        pourboire = lire_reel("Pourboire ($) : ")
        print()
        afficher_facture(quantites, rabais, pourboire)


main()
```

> 💡 Les commentaires en bandeau (`# ----- Constantes -----`) ne sont pas obligatoires, mais ils aident à repérer les sections dans un long fichier. On peut aussi utiliser `Ctrl + Maj + O` dans VS Code pour afficher la liste des fonctions du fichier et y sauter directement.

### Pourquoi une fonction `main()`?

On pourrait écrire le programme principal directement en bas du fichier, sans le mettre dans une fonction. Le regrouper dans `main()` a plusieurs avantages :

- **Les variables du programme deviennent locales.** `quantites`, `choix` ou `rabais` n'existent que dans `main()`. Aucune autre fonction ne peut donc s'en servir par accident : elles doivent les recevoir en paramètres, comme le recommande [7.5 - La portée des variables](7.5%20-%20La%20portée%20des%20variables.md).
- **Le programme se lit comme une table des matières.** En lisant `main()`, on comprend tout le déroulement sans entrer dans les détails.
- **Le point de départ est clair.** Tout commence au seul appel placé tout en bas du fichier : `main()`.

> 📌 Le nom `main` (« principal », en anglais) est une convention reprise de plusieurs autres langages, comme C, C++, Java et C#.

## 3. Le déroulement de l'exécution

Python lit le fichier de haut en bas :

1. Il **mémorise** les constantes.
2. Il **mémorise** chacune des fonctions, **sans les exécuter**.
3. Il rencontre `main()`, la seule instruction qui déclenche réellement quelque chose : il **saute** dans `main()`.
4. `main()` appelle `afficher_menu()`, qui appelle `afficher_entete()`, qui appelle `afficher_separateur()`… À chaque appel terminé, l'exécution **revient** à la ligne suivante de la fonction appelante.
5. Quand `main()` se termine, l'exécution revient tout en bas du fichier, et le programme se termine.

```text
main()
 ├─ afficher_menu()
 │   └─ afficher_entete()
 │       └─ afficher_separateur("=")   (2 fois)
 ├─ lire_entier(...)                   (une fois par saisie)
 ├─ ajouter_au_panier(...)
 ├─ lire_oui_non(...)
 ├─ lire_reel(...)
 └─ afficher_facture(...)
     ├─ afficher_entete()
     ├─ afficher_ligne(...)            (une fois par produit commandé)
     ├─ calculer_sous_total(...)
     ├─ calculer_rabais(...)
     ├─ calculer_taxes(...)
     ├─ afficher_montant(...)
     └─ calculer_total(...)
         ├─ calculer_rabais(...)
         └─ calculer_taxes(...)
```

> 💡 Pour voir ce déroulement en direct, place un point d'arrêt (`F9`) sur la ligne `main()`, puis avance avec `F11` (**Pas à pas détaillé**) pour entrer dans les fonctions, ou `F10` (**Pas à pas principal**) pour exécuter un appel d'un seul coup sans y entrer.

## 4. Le modèle à 2 fichiers

### Le problème

Les fonctions `lire_entier()`, `lire_reel()` et `lire_oui_non()` n'ont **rien de spécifique au café**. Elles seraient utiles dans n'importe quel programme qui fait des saisies… comme les prochains travaux pratiques. Les recopier dans chaque nouveau programme, ce serait revenir au problème du copier-coller de la fiche [7.1](7.1%20-%20Pourquoi%20des%20fonctions.md).

### La solution : un module

Un **module**, c'est simplement **un fichier `.py`** dont on peut importer les fonctions dans un autre fichier. C'est exactement ce qu'on fait déjà avec `import math` ou `import random` : `math` et `random` sont des modules fournis avec Python.

On répartit donc le code en deux fichiers, placés **dans le même dossier** :

```text
Caisse/
├── caisse.py         ← programme principal : constantes, fonctions du café, main()
└── utilitaires.py    ← fonctions réutilisables : lire_entier(), lire_reel(), lire_oui_non()
```

| Fichier | Contient | Réutilisable ailleurs? |
| --- | --- | --- |
| `utilitaires.py` | Les fonctions générales, qui ne dépendent d'aucune constante du café | ✅ Oui, tel quel |
| `caisse.py` | Les constantes, les fonctions propres au café, et `main()` | ❌ Non, c'est le programme lui-même |

### Le fichier `utilitaires.py`

```python
"""Fonctions utilitaires de saisie validée.

Ces fonctions ne dépendent d'aucun programme en particulier : on peut les
importer dans n'importe quel projet qui doit lire des données au clavier.
"""


def lire_entier(message, minimum=0, maximum=99):
    """Demande un nombre entier jusqu'à ce que la saisie soit valide.
    ...
    """
    ...


def lire_reel(message, minimum=0.0):
    ...


def lire_oui_non(message):
    ...
```

Voir le fichier complet : [utilitaires.py](Exemples/2%20fichiers/utilitaires.py).

### Le fichier `caisse.py`

Les trois fonctions de saisie disparaissent de `caisse.py`. À la place, une ligne d'**import** est ajoutée dans la section des imports :

```python
"""Caisse du Café Le Binaire.

Prend la commande d'un client, puis affiche sa facture avec le rabais
étudiant, les taxes et le pourboire.
"""

from utilitaires import lire_entier, lire_reel, lire_oui_non

# Constantes
NOM_CAFE = "Café Le Binaire"
...

# Fonctions d'affichage et de calcul (inchangées)
...

def main():
    ...
    choix = lire_entier("Votre choix : ", 0, len(PRODUITS))   # vient de utilitaires.py
    ...


main()
```

Le reste du programme est **identique**. Voir le fichier complet : [caisse.py](Exemples/2%20fichiers/caisse.py).

Pour exécuter le programme, on lance **`caisse.py`**, comme d'habitude. Python va lui-même chercher `utilitaires.py` au moment de l'import.

## 5. Deux façons d'importer

| Forme | Appel de la fonction | Quand l'utiliser |
| --- | --- | --- |
| `import utilitaires` | `utilitaires.lire_entier("Quantité : ")` | On importe tout le module; le préfixe indique clairement d'où vient la fonction. |
| `from utilitaires import lire_entier, lire_reel` | `lire_entier("Quantité : ")` | On importe seulement les fonctions nommées, qu'on appelle sans préfixe. |

```python
# Forme 1 : on importe le module
import utilitaires

quantite = utilitaires.lire_entier("Quantité : ", 1, 20)
```

```python
# Forme 2 : on importe des fonctions précises
from utilitaires import lire_entier

quantite = lire_entier("Quantité : ", 1, 20)
```

> 💡 La forme 1 est celle qu'on utilise avec `math` : `import math`, puis `math.sqrt(25)`. Les deux formes sont correctes; l'important est d'être cohérent dans un même programme.

## 6. Règles et pièges

### Les deux fichiers doivent être dans le même dossier

Python cherche d'abord le module dans le dossier du programme qu'on exécute. S'il ne le trouve pas :

```text
ModuleNotFoundError: No module named 'utilitaires'
```

### Le nom du fichier doit être un nom valide

Dans l'instruction `import`, on écrit le nom du fichier **sans** l'extension `.py`. Ce nom doit donc respecter les règles d'un nom de variable : lettres minuscules, chiffres et soulignements, **sans espaces ni tirets**.

| ❌ À éviter | ✅ Bon |
| --- | --- |
| `mes fonctions.py` | `mes_fonctions.py` |
| `outils-saisie.py` | `outils_saisie.py` |

### Ne pas nommer un fichier comme un module de Python

Si on nomme un fichier `random.py` ou `math.py`, l'instruction `import random` importera **notre** fichier au lieu du module de Python, avec des erreurs très déroutantes à la clé. C'est un piège fréquent quand on nomme un fichier d'exercice d'après le sujet étudié!

### Le dossier `__pycache__`

Après une première exécution, un dossier `__pycache__` apparaît à côté des fichiers. Python y conserve une version précompilée des modules importés pour les charger plus vite la fois suivante. On peut l'ignorer (ou le supprimer) sans problème : il sera recréé au besoin.

## 7. Complément : `if __name__ == "__main__":`

Lorsqu'on écrit un module comme `utilitaires.py`, on voudrait pouvoir **tester ses fonctions** en l'exécutant directement… sans que ces tests s'exécutent chaque fois qu'un autre programme l'importe.

Python fournit pour cela une variable spéciale, `__name__`, qui vaut :

- `"__main__"` si le fichier est **exécuté directement** (avec le bouton ▶ de VS Code, par exemple);
- le **nom du module** (ici, `"utilitaires"`) si le fichier est **importé** par un autre.

On place donc les tests sous cette condition, à la fin du module :

```python
# À la fin de utilitaires.py

# Tests rapides : exécutés seulement si on lance ce fichier directement,
# jamais lorsqu'il est importé par un autre fichier.
if __name__ == "__main__":
    age = lire_entier("Âge (0 à 120) : ", 0, 120)
    print("Entier lu :", age)
    montant = lire_reel("Montant : ")
    print("Réel lu :", montant)
    print("Réponse :", lire_oui_non("Continuer? (o/n) : "))
```

| Ce qu'on exécute | `__name__` dans `utilitaires.py` | Les tests s'exécutent? |
| --- | --- | --- |
| `utilitaires.py` | `"__main__"` | ✅ Oui |
| `caisse.py` (qui importe `utilitaires`) | `"utilitaires"` | ❌ Non |

> 💡 On rencontre souvent cette même condition à la fin d'un programme principal, autour de l'appel à `main()` :
>
> ```python
> if __name__ == "__main__":
>     main()
> ```
>
> Elle permet d'importer les fonctions de `caisse.py` dans un autre fichier (pour les tester, par exemple) sans lancer toute la caisse.

## 8. Le programme Python type

### Modèle à 1 fichier

```python
"""Docstring : ce que fait le programme."""

# 1. Imports
import math

# 2. Constantes
CONSTANTE = 42


# 3. Fonctions
def calculer_quelque_chose(parametre):
    """Docstring de la fonction."""
    return ...


# 4. Programme principal
def main():
    """Point de départ du programme."""
    ...


main()
```

### Modèle à 2 fichiers

```python
# utilitaires.py
"""Docstring : fonctions réutilisables."""


def fonction_generale(parametre):
    """Docstring de la fonction."""
    return ...


if __name__ == "__main__":
    # tests rapides des fonctions
    ...
```

```python
# programme.py
"""Docstring : ce que fait le programme."""

# 1. Imports (y compris nos propres modules)
from utilitaires import fonction_generale

# 2. Constantes
CONSTANTE = 42


# 3. Fonctions propres au programme
def calculer_quelque_chose(parametre):
    """Docstring de la fonction."""
    return ...


# 4. Programme principal
def main():
    """Point de départ du programme."""
    ...


main()
```

## En résumé

- Ordre type d'un fichier : **docstring**, **imports**, **constantes**, **fonctions**, **`main()`**, puis l'**appel** de `main()`.
- Le programme principal est regroupé dans `main()` : ses variables restent locales, et le programme se lit comme une table des matières.
- Python mémorise d'abord toutes les fonctions; l'exécution réelle commence à l'appel de `main()`.
- Un **module** est un simple fichier `.py`. On y place les fonctions réutilisables, puis on les importe avec `import module` ou `from module import fonction`.
- Le module doit être dans le même dossier, avoir un nom valide et ne pas porter le nom d'un module de Python.
- `if __name__ == "__main__":` permet de placer des tests dans un module sans qu'ils s'exécutent lorsqu'il est importé.
