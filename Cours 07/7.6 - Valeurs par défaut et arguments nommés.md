# Valeurs par défaut et arguments nommés

## Objectifs

- Donner une valeur par défaut à un paramètre pour le rendre optionnel.
- Respecter l'ordre des paramètres obligatoires et optionnels.
- Passer des arguments **par leur nom** plutôt que par leur position.
- Combiner arguments positionnels et arguments nommés.
- Reconnaître ces mécanismes dans des fonctions déjà utilisées (`print()`, `sort()`, `round()`).

## 1. Principe

Certains paramètres prennent presque toujours la même valeur. Dans la caisse, la plupart des clients n'ont pas de rabais et ne laissent pas de pourboire. Les obliger à fournir `0.0` à chaque appel alourdit le code :

```python
total = calculer_total(17.10, 0.0, 0.0)   # 0.0 de rabais, 0.0 de pourboire
```

Une **valeur par défaut** rend un paramètre **optionnel** : si on ne fournit pas l'argument, le paramètre prend cette valeur.

```python
def nom_de_la_fonction(obligatoire, optionnel=valeur_par_defaut):
    ...
```

> 💡 Par convention ([PEP 8](https://peps.python.org/pep-0008/#other-recommendations)), on n'ajoute **pas d'espaces** autour du `=` d'une valeur par défaut : `rabais=0.0`, et non `rabais = 0.0`.

## 2. Valeurs par défaut

```python
def calculer_total(sous_total, rabais=0.0, pourboire=0.0):
    montant = sous_total - calculer_rabais(sous_total, rabais)
    tps, tvq = calculer_taxes(montant)
    return round(montant + tps + tvq + pourboire, 2)
```

> `calculer_rabais()` et `calculer_taxes()` sont les fonctions vues en [7.4 - Renvoyer une valeur](7.4%20-%20Renvoyer%20une%20valeur.md). `calculer_rabais(montant, taux)` renvoie simplement `round(montant * taux, 2)`.

Le paramètre `sous_total` est **obligatoire**; `rabais` et `pourboire` sont **optionnels**. On peut donc appeler la fonction de plusieurs façons :

```python
print(calculer_total(17.10))               # 19.67 : sans rabais ni pourboire
print(calculer_total(17.10, 0.10))         # 17.70 : rabais étudiant de 10 %
print(calculer_total(17.10, 0.10, 2.50))   # 20.20 : rabais et pourboire
```

Les arguments fournis remplissent les paramètres **dans l'ordre**; ceux qui manquent prennent leur valeur par défaut.

### Les paramètres optionnels viennent après les obligatoires

Puisque les arguments sont associés par position, Python ne pourrait pas deviner quel argument va où si un paramètre obligatoire suivait un paramètre optionnel. C'est donc interdit :

```python
# ❌ Mauvais : un paramètre obligatoire suit un paramètre optionnel
def calculer_total(rabais=0.0, sous_total):
    ...
```

```text
SyntaxError: parameter without a default follows parameter with a default
```

```python
# ✅ Bon : d'abord les obligatoires, ensuite les optionnels
def calculer_total(sous_total, rabais=0.0, pourboire=0.0):
    ...
```

### Rendre `lire_entier()` plus pratique

La fonction `lire_entier()` de la fiche 7.4 exigeait toujours un minimum et un maximum. Avec des valeurs par défaut, on couvre le cas le plus fréquent (une quantité raisonnable) tout en gardant la possibilité de préciser les bornes :

```python
def lire_entier(message, minimum=0, maximum=99):
    valide = False
    while not valide:
        try:
            valeur = int(input(message))
            if minimum <= valeur <= maximum:
                valide = True
            else:
                print(f"Erreur : entrez un nombre entre {minimum} et {maximum}.")
        except ValueError:
            print("Erreur : ce n'est pas un nombre entier.")
    return valeur


nb_tasses = lire_entier("Nombre de tasses : ")                  # entre 0 et 99
choix = lire_entier("Votre choix : ", 0, len(PRODUITS))        # entre 0 et 5
quantite = lire_entier("Quantité : ", 1, QUANTITE_MAX)          # entre 1 et 20
```

## 3. Arguments nommés

Comment donner un pourboire **sans** rabais? Par position, on est obligé de fournir le rabais, même s'il vaut la valeur par défaut :

```python
total = calculer_total(17.10, 0.0, 2.50)   # que représentent 0.0 et 2.50?
```

Python permet plutôt d'**écrire le nom du paramètre** devant l'argument. On parle d'**argument nommé** (*keyword argument*, en anglais) :

```python
total = calculer_total(17.10, pourboire=2.50)
```

Le paramètre `pourboire` reçoit `2.50`, et `rabais` garde sa valeur par défaut. En prime, l'appel se lit tout seul : on sait exactement ce que représente chaque valeur.

### L'ordre n'a plus d'importance

Avec des arguments nommés, c'est le **nom** qui fait l'association, pas la position :

```python
calculer_total(17.10, rabais=0.10, pourboire=2.50)
calculer_total(17.10, pourboire=2.50, rabais=0.10)       # même résultat
calculer_total(pourboire=2.50, rabais=0.10, sous_total=17.10)  # même résultat
```

### Les arguments positionnels d'abord

On peut combiner les deux sortes d'arguments, à une condition : les arguments **positionnels** viennent **avant** les arguments **nommés**.

```python
# ❌ Mauvais : un argument positionnel suit un argument nommé
calculer_total(rabais=0.10, 17.10)
```

```text
SyntaxError: positional argument follows keyword argument
```

```python
# ✅ Bon
calculer_total(17.10, rabais=0.10)
```

> 💡 Les arguments nommés fonctionnent avec **tous** les paramètres, optionnels ou non. On les utilise surtout pour les paramètres optionnels, ou lorsque l'appel serait difficile à lire autrement (plusieurs nombres à la suite, des `True`/`False`, etc.).

## 4. Tu les utilises déjà (!)

Plusieurs fonctions et méthodes de Python ont des paramètres optionnels, que l'on fournit par leur nom :

| Appel | Paramètre optionnel | Valeur par défaut |
| --- | --- | --- |
| `print("Latté", end="")` | `end` : ce qui est affiché à la fin | `"\n"` (un saut de ligne) |
| `print("2", "50", sep=",")` | `sep` : ce qui sépare les valeurs | `" "` (une espace) |
| `prix.sort(reverse=True)` | `reverse` : trier en ordre décroissant | `False` |
| `round(2.256, ndigits=2)` | `ndigits` : nombre de décimales | aucune décimale |

Par exemple, quand on écrit `print(f"{i}. ", end="")`, on appelle `print()` en laissant `sep` à sa valeur par défaut et en fournissant `end` par son nom. C'est exactement le mécanisme de cette fiche.

## 5. Bonnes pratiques

### Choisir une valeur par défaut qui correspond au cas le plus fréquent

La valeur par défaut doit être celle qu'on utiliserait « normalement ». Pour un rabais ou un pourboire, c'est `0.0`. Si aucune valeur n'est vraiment plus fréquente que les autres, le paramètre devrait rester obligatoire.

### Nommer les arguments booléens et les nombres ambigus

```python
# ❌ Difficile à lire : que signifient 0.10 et 2.50?
calculer_total(17.10, 0.10, 2.50)
```

```python
# ✅ Bon : l'appel s'explique de lui-même
calculer_total(17.10, rabais=0.10, pourboire=2.50)
```

## En résumé

- `def f(a, b=valeur):` donne une **valeur par défaut** à `b`, qui devient **optionnel**.
- Les paramètres **obligatoires** viennent avant les paramètres **optionnels**.
- Un **argument nommé** (`pourboire=2.50`) est associé au paramètre par son nom, peu importe sa position.
- On peut combiner les deux, mais les arguments **positionnels** viennent toujours **en premier**.
- `print(end="")`, `sort(reverse=True)` et `round(ndigits=2)` utilisent ces mêmes mécanismes.
