# La portée des variables

## Objectifs

- Comprendre ce qu'est la **portée** d'une variable.
- Distinguer une variable **locale** d'une variable **globale**.
- Savoir qu'une fonction peut lire les constantes du programme.
- Reconnaître le piège d'une variable locale qui porte le même nom qu'une variable globale.
- Comprendre pourquoi une fonction peut modifier une liste reçue en paramètre, mais pas une variable simple.
- Faire entrer les données par les paramètres et les faire sortir par `return`.

## 1. Principe

La **portée** d'une variable, c'est la partie du programme où cette variable **existe** et peut être utilisée.

| Sorte de variable | Où est-elle créée? | Où peut-on l'utiliser? |
| --- | --- | --- |
| **Locale** | Dans le corps d'une fonction (y compris ses paramètres) | Seulement dans cette fonction, pendant l'appel |
| **Globale** | En dehors de toute fonction, au premier niveau du fichier | Partout dans le fichier, après sa création |

## 2. Les variables locales

Chaque appel de fonction crée son propre **espace** de variables. Les variables créées dans la fonction, de même que ses paramètres, y vivent le temps de l'appel… puis **disparaissent** dès que la fonction se termine.

```python
PRIX = (2.25, 4.50, 3.75, 3.25, 1.95)


def calculer_sous_total(quantites):
    sous_total = 0.0
    for i in range(len(quantites)):
        sous_total += quantites[i] * PRIX[i]
    return sous_total


calculer_sous_total([1, 2, 0, 0, 3])
print(sous_total)
```

```text
NameError: name 'sous_total' is not defined
```

Les variables `sous_total`, `i` et `quantites` sont **locales** à `calculer_sous_total()`. Le programme principal ne peut pas les voir. La seule façon de récupérer le résultat, c'est la **valeur renvoyée** :

```python
# ✅ Bon : on récupère la valeur renvoyée par la fonction
montant = calculer_sous_total([1, 2, 0, 0, 3])
print(montant)    # 17.1
```

> 💡 C'est une bonne nouvelle : on peut nommer une variable `i` ou `total` dans une fonction sans craindre d'écraser une variable du même nom ailleurs dans le programme.

## 3. Lire les constantes globales

Une fonction peut **lire** une variable globale. C'est ce qu'on fait depuis le début du cours avec les constantes : elles sont définies en haut du fichier et ont une portée globale (voir [2.3 - Constantes](../Cours%2002/2.3%20-%20Constantes.md)).

```python
TAUX_TPS = 0.05
TAUX_TVQ = 0.09975


def calculer_taxes(montant):
    tps = round(montant * TAUX_TPS, 2)    # lecture de la constante globale TAUX_TPS
    tvq = round(montant * TAUX_TVQ, 2)    # lecture de la constante globale TAUX_TVQ
    return tps, tvq
```

Lorsque Python rencontre un nom dans une fonction, il le cherche d'abord **parmi les variables locales**, puis, s'il ne l'y trouve pas, **parmi les variables globales**.

> 📌 Lire une **constante** dans une fonction est une pratique normale et recommandée : sa valeur ne change jamais. Par contre, une fonction ne devrait **pas** dépendre d'une variable globale ordinaire, dont la valeur peut changer au fil du programme. Ce qui varie doit entrer par les **paramètres**.

## 4. Piège : une variable locale qui masque une globale

Si une fonction **affecte** une valeur à un nom (avec `=`), Python crée une **nouvelle variable locale**, même si une variable globale du même nom existe déjà. La variable globale n'est pas modifiée.

```python
total = 0.0    # variable globale


def ajouter_pourboire(montant, pourboire):
    total = montant + pourboire    # nouvelle variable LOCALE, sans lien avec la globale
    print(f"Total dans la fonction : {total:.2f} $")


ajouter_pourboire(17.70, 2.50)
print(f"Total après l'appel : {total:.2f} $")
```

```text
Total dans la fonction : 20.20 $
Total après l'appel : 0.00 $
```

Les deux `total` sont deux variables différentes qui portent le même nom. C'est une source fréquente de confusion.

```python
# ✅ Bon : la fonction renvoie le résultat, et l'appelant décide où le ranger
def ajouter_pourboire(montant, pourboire):
    return montant + pourboire


total = ajouter_pourboire(17.70, 2.50)
print(f"Total : {total:.2f} $")    # Total : 20.20 $
```

## 5. Modifier un paramètre : variable simple ou liste?

### Réaffecter un paramètre ne change rien à l'extérieur

Réaffecter un paramètre avec `=` ne fait que donner une **nouvelle valeur à la variable locale**. La variable d'origine, à l'extérieur de la fonction, n'est pas touchée :

```python
def appliquer_rabais(montant):
    montant = montant * 0.90    # change seulement le paramètre local


sous_total = 17.10
appliquer_rabais(sous_total)
print(sous_total)    # 17.1 : aucun changement!
```

Pour obtenir le nouveau montant, la fonction doit le **renvoyer** :

```python
def appliquer_rabais(montant):
    return montant * 0.90


sous_total = 17.10
sous_total = appliquer_rabais(sous_total)
print(round(sous_total, 2))    # 15.39
```

### Le contenu d'une liste, lui, peut être modifié

Lorsqu'on passe une **liste** en argument, le paramètre et la variable d'origine désignent **la même liste**. C'est le même phénomène que l'*alias* vu en [6.2 - Les listes](../Cours%2006/6.2%20-%20Les%20listes.md) avec `b = a`. Si la fonction modifie le **contenu** de la liste (par index, `append()`, etc.), la modification est visible à l'extérieur.

La caisse s'en sert pour ajouter des produits au panier :

```python
def ajouter_au_panier(quantites, index, quantite):
    quantites[index] += quantite


panier = [0, 0, 0, 0, 0]
ajouter_au_panier(panier, 1, 2)    # 2 lattés
ajouter_au_panier(panier, 4, 3)    # 3 biscuits
print(panier)                      # [0, 2, 0, 0, 3]
```

`ajouter_au_panier()` ne renvoie rien : elle **modifie directement** la liste reçue.

| L'argument est… | La fonction modifie… | Effet à l'extérieur |
| --- | --- | --- |
| N'importe quoi | le paramètre lui-même (`montant = ...`) | ❌ Aucun : il faut utiliser `return` |
| Une liste | le **contenu** de la liste (`quantites[i] = ...`, `append()`) | ✅ La liste d'origine est modifiée |

> ⚠️ Modifier une liste reçue en paramètre est parfois voulu (comme ici), mais peut aussi surprendre. Lorsqu'une fonction modifie une liste, son nom doit l'indiquer clairement (`ajouter_au_panier`, `vider_panier`, etc.).

## 6. La bonne pratique : entrées par les paramètres, sorties par `return`

Une fonction bien écrite est **autonome** : tout ce dont elle a besoin entre par ses **paramètres** (ou vient de constantes), et tout ce qu'elle produit sort par son **`return`**.

```text
             ┌───────────────────────────┐
paramètres ─►│   variables locales       │─► return
             │   (+ lecture constantes)  │
             └───────────────────────────┘
```

Une telle fonction :

- donne toujours le même résultat pour les mêmes arguments;
- peut être testée seule, sans le reste du programme;
- peut être copiée dans un autre programme sans rien briser.

```python
# ❌ Mauvais : la fonction dépend d'une variable globale qui change
pourboire = 0.0

def calculer_total(sous_total):
    return sous_total + pourboire
```

```python
# ✅ Bon : tout ce qui varie entre par les paramètres
def calculer_total(sous_total, pourboire):
    return sous_total + pourboire
```

## En résumé

- La **portée** d'une variable est la partie du programme où elle existe.
- Les variables créées dans une fonction, et ses paramètres, sont **locales** : elles disparaissent à la fin de l'appel.
- Une fonction peut **lire** les constantes globales; ce qui varie doit plutôt entrer par les paramètres.
- Affecter une valeur à un nom dans une fonction crée une variable locale, même si une globale porte le même nom.
- Réaffecter un paramètre ne modifie pas la variable d'origine; modifier le **contenu** d'une liste reçue, oui.
- Bonne pratique : les données **entrent par les paramètres** et **sortent par `return`**.
