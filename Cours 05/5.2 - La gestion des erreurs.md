# La gestion des erreurs en Python

## Objectifs

- Comprendre ce qu'est une exception et pourquoi elle interrompt le programme.
- Reconnaître les exceptions les plus courantes (`ValueError`, `TypeError`, `ZeroDivisionError`, etc.).
- Utiliser l'instruction `try` et sa clause `except` pour intercepter une exception.
- Cibler un type d'exception précis plutôt qu'une clause `except` générique.
- Combiner `try`/`except` avec une boucle `while` pour redemander une saisie invalide.

## 1. Principe

Une **exception** est une erreur qui survient pendant l'**exécution** du programme (contrairement à une erreur de syntaxe, détectée avant même que le programme démarre). Sans intervention, une exception **arrête immédiatement** le programme.

```python
age = int(input("Entrez votre âge : "))
print("Vous avez", age, "ans.")
```

Si l'utilisateur tape `vingt` au lieu de `20`, Python affiche une erreur et le programme s'arrête :

```text
ValueError: invalid literal for int() with base 10: 'vingt'
```

Le nom avant le `:` (ici `ValueError`) est le **type de l'exception**. Voici les erreurs d'exécution les plus courantes :

| Exception | Se produit quand... | Exemple |
| --- | --- | --- |
| `ValueError` | une valeur a le bon type, mais une valeur inutilisable | `int("vingt")` |
| `TypeError` | une opération est appliquée à un type incompatible | `"3" + 3` |
| `ZeroDivisionError` | on divise un nombre par zéro | `10 / 0` |
| `NameError` | on utilise une variable qui n'a jamais été définie | `print(nombre)` sans avoir créé `nombre` |

> ⚠️ La structure `try`/`except` n'intercepte que des erreurs **d'exécution.**  
>
> Les erreurs **de syntaxe** (`SyntaxError`, `IndentationError`, vues dans la fiche [2.6 - Lire une erreur de syntaxe](../Cours%2002/2.6%20-%20Lire%20une%20erreur%20de%20syntaxe.md)) sont quant à elles détectées **avant** que le programme démarre : aucune ligne ne s'exécute encore, donc le `try` lui-même n'a pas encore eu la chance de s'exécuter. Un `try`/`except` ne peut donc jamais « réparer » une erreur de syntaxe.

## 2. L'instruction `try`

`try` et `except` sont des **mots-clés** réservés de Python. Ensemble, ils forment une **instruction composée** appelée l'**instruction `try`**. Le bloc introduit par `except` est appelé une **clause `except`** — exactement comme `elif` et `else` sont des clauses de l'instruction `if`.

Cette instruction possède d'autres clauses (`else`, `finally`) qui seront couvertes plus tard dans le cours. Pour l'instant, on se concentre sur les deux clauses essentielles : `try` et `except`.

```python
try:
    # bloc try : instructions qui pourraient provoquer une erreur
except TypeDeLErreur as nom_erreur:
    # clause except : exécutée seulement si une erreur de type TypeDeLErreur survient dans le bloc try. On utilise un alias avec `as` pour accéder à l'erreur interceptée, au besoin.
```

- Python exécute d'abord le bloc `try`.
- Si une erreur survient, il **saute immédiatement** à la clause `except`, sans exécuter le reste du bloc `try`.
- Si aucune erreur ne survient, la clause `except` est simplement ignorée.

## 3. Exemple simple

```python
try:
    age = int(input("Entrez votre âge : "))
    print("Vous avez", age, "ans.")
except ValueError as erreur:
    print("Ce n'est pas un nombre valide.")
    print(erreur)
```

Peu importe ce que l'utilisateur tape, le programme ne plante plus : soit l'âge s'affiche, soit le message d'erreur s'affiche.

## 4. Cibler une exception précise

La clause `except` nue (sans préciser de type) intercepte **toutes** les erreurs, même celles qu'on n'avait pas prévues — ce qui peut cacher un vrai bug dans le programme. Il est préférable de cibler le type d'exception attendu.

```python
# ❌ Mauvais : intercepte n'importe quelle erreur, trop générique
try:
    age = int(input("Entrez votre âge : "))
except:
    print("Ce n'est pas un nombre valide.")
```

```python
# ✅ Bon : on cible précisément l'erreur qu'on attend
try:
    age = int(input("Entrez votre âge : "))
except ValueError:
    print("Ce n'est pas un nombre valide.")
```

Avec la version ciblée, si une autre erreur survient (une qu'on n'avait pas prévue), Python continue de l'afficher normalement plutôt que de la cacher silencieusement.

## 5. Combiner avec une boucle `while` pour la validation des saisies

Un simple `try`/`except` empêche le programme de planter, mais n'insiste pas pour obtenir une valeur valide. En combinant avec une boucle `while` et un **drapeau** (voir [5.1 - La boucle while](5.1%20-%20La%20boucle%20while.md)), on peut redemander la saisie jusqu'à ce qu'elle soit valide.

```python
valide = False # drapeau
while not valide:
    try:
        age = int(input("Entrez votre âge : "))
        valide = True # atteint seulement si int() n'a pas levé d'erreur
    except ValueError:
        print("Ce n'est pas un nombre valide. Réessayez.")
# Rendu ici, on est ASSURÉ que la variable `age` a une valeur valide,
# donc on peut l'afficher sans souci!
print("Vous avez", age, "ans.")
```

Le drapeau `valide` n'est mis à `True` que si la ligne `int(input(...))` s'est déroulée sans erreur. Tant que l'utilisateur entre du texte, l'exception est interceptée, le drapeau reste `False`, et la boucle recommence.

## En résumé

- Une exception interrompt le programme si elle n'est pas interceptée.
- `try` et `except` sont des mots-clés qui forment ensemble l'**instruction `try`** : le bloc `try` contient le code à risque, la **clause `except`** contient la réaction à l'erreur.
- Toujours cibler le type d'exception attendu (`except ValueError:`) plutôt qu'une clause `except` nue.
- Combinée à une boucle `while` et à un drapeau, l'instruction `try` permet de redemander une saisie jusqu'à ce qu'elle soit valide.
