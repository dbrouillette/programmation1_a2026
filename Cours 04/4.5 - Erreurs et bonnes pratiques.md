# Erreurs courantes et bonnes pratiques avec les conditions

## Objectifs

- Reconnaître et éviter les erreurs les plus fréquentes avec les structures conditionnelles.
- Adopter des habitudes qui rendent les conditions plus lisibles et plus sûres.

## Partie 1 — Erreurs courantes

### 1.1 Confondre `=` et `==`

```python
age = 18
if age = 18:        # ❌ SyntaxError — `=` est une affectation, pas une comparaison
    print("Majeur")

if age == 18:        # ✅ correct
    print("Majeur")
```

En Python, cette erreur provoque heureusement une `SyntaxError` immédiate (contrairement à certains langages où elle passe silencieusement).

### 1.2 Comparer explicitement à `True`/`False`

```python
est_actif = True

if est_actif == True:   # fonctionne, mais redondant
    print("Actif")

if est_actif:            # ✅ préférable — une variable booléenne est déjà une condition
    print("Actif")
```

De même, `if not est_actif:` est préférable à `if est_actif == False:`.

### 1.3 Oublier que `elif` s'arrête à la première condition vraie

```python
note = 95

if note >= 50:
    print("Passable")
elif note >= 90:
    print("Excellent")   # ⚠️ jamais atteint, voir fiche 4.2, section 3
```

### 1.4 Un `else` mal positionné ou orphelin

```python
if age >= 18:
    print("Majeur")
    else:                 # ❌ IndentationError — else doit être aligné avec le if
        print("Mineur")
```

Le `else` (comme le `elif`) doit toujours être **aligné exactement** avec le `if` auquel il se rattache.

### 1.5 Indentation incohérente

```python
if age >= 18:
    print("Majeur")
      print("Bienvenue")   # ❌ IndentationError — indentation incohérente dans le même bloc
```

Toutes les lignes d'un même bloc doivent avoir **exactement la même indentation**. Mélanger tabulations et espaces peut aussi causer ce type d'erreur, même si le code semble aligné visuellement.

## Partie 2 — Bonnes pratiques

### 2.1 Préférer `elif` à des `if` en cascade lorsque les cas s'excluent

```python
# Moins clair
if note >= 90:
    print("Excellent")
if note < 90 and note >= 75:
    print("Très bien")

# Plus clair
if note >= 90:
    print("Excellent")
elif note >= 75:
    print("Très bien")
```

### 2.2 Combiner des conditions avec `and`/`or` plutôt qu'imbriquer sans raison

```python
# Imbriqué sans raison
if age >= 18:
    if permis_voiture:
        print("Vous pouvez conduire.")

# Plus direct
if age >= 18 and permis_voiture:
    print("Vous pouvez conduire.")
```

### 2.3 Sortie anticipée (« guard clause ») pour éviter l'imbrication profonde

Plutôt que d'imbriquer les cas valides les uns dans les autres, on peut **traiter les cas invalides en premier et sortir tôt** :

```python
# Imbriqué
def verifier_acces(age, a_accepte):
    if age >= 18:
        if a_accepte:
            print("Accès autorisé")
        else:
            print("Vous devez accepter les conditions")
    else:
        print("Accès refusé : mineur")

# Avec guard clauses
def verifier_acces(age, a_accepte):
    if age < 18:
        print("Accès refusé : mineur")
        return
    if not a_accepte:
        print("Vous devez accepter les conditions")
        return
    print("Accès autorisé")
```

### 2.4 Utiliser des comparaisons enchaînées pour la lisibilité

```python
# Moins lisible
if age >= 18 and age <= 25:
    print("Jeune adulte")

# Plus lisible (comparaison enchaînée à la Python)
if 18 <= age <= 25:
    print("Jeune adulte")
```

### 2.5 Toujours prévoir le cas par défaut

Un `else` final (même s'il ne fait qu'afficher un message d'erreur) évite qu'un cas imprévu passe inaperçu :

```python
if note < 0 or note > 100:
    print("Note invalide")
elif note >= 50:
    print("Réussite")
else:
    print("Échec")
```

## En résumé

- Les erreurs les plus fréquentes viennent de la confusion `=`/`==`, d'une indentation incohérente, ou d'un mauvais ordre des `elif`.
- Une variable booléenne se teste directement (`if est_actif:`). Ne pas la comparer à `True`/`False`, c'est inutile.
- Ne jamais comparer des `float` avec `==` ou `!=`. Utiliser `math.isclose()`.
- Pour la lisibilité du code :
  - préférer `elif` aux `if` en cascade;
  - combiner avec `and`/`or` plutôt qu'imbriquer sans raison;
  - prévoir systématiquement un cas par défaut.
