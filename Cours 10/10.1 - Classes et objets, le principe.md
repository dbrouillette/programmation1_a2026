# Classes et objets : le principe

## Objectifs

- Comprendre ce qu'est un **objet** et ce qu'est une **classe**.
- Définir une classe avec son **constructeur** `__init__()`.
- Créer des objets et utiliser leurs **attributs**.
- Comprendre le rôle de `self`.

> 📋 **Prérequis** : les fonctions (cours 7) et les dictionnaires (cours 9).

> 🦊 **Fil conducteur** : dans les fiches 10.1 à 10.4, on programme les renards d'un refuge faunique.

## 1. Principe

Avec ce qu'on connaît du cours 9, un renard serait un **dictionnaire** :

```python
renard = {"nom": "Roux", "couleur": "roux", "age": 3, "energie": 50, "proies": []}
```

Ça fonctionne, mais :

- une faute de frappe dans une clé (`renard["énergie"]`) n'est détectée qu'à l'exécution, par une `KeyError`;
- rien ne garantit que **tous** les renards ont les mêmes clés;
- les fonctions qui travaillent sur un renard (`chasser(renard, proie)`, `courir(renard, distance)`) sont dispersées dans le programme.

La **programmation orientée objet** regroupe au même endroit :

- les **données** qui décrivent une chose (le nom du renard, sa couleur, son âge, son énergie);
- les **actions** qu'on peut faire avec cette chose (chasser, courir, glapir).

Cette « chose » s'appelle un **objet**. Et le plan qui décrit à quoi ressemblent tous les objets d'une même sorte s'appelle une **classe**.

> 💡 **Analogie** : la classe `Renard`, c'est la **fiche descriptive** de l'espèce : un renard a un nom, une couleur, un âge, de l'énergie, et il sait chasser et courir. Roux, Flocon et Cendre sont trois **objets** : trois vrais renards, chacun avec son propre nom et sa propre énergie, mais qui suivent tous la même fiche.

Tu utilises des objets depuis le cours 1 sans le savoir! Une chaîne est un objet de la classe `str`, et `upper()` est une de ses méthodes. Une liste est un objet de la classe `list`, et `append()` est une de ses méthodes.

```python
nom = "roux"
print(type(nom))         # <class 'str'>
print(nom.upper())       # ROUX : la méthode upper() de l'objet nom
```

Dans ce cours, on va créer **nos propres** classes.

## 2. Définir une classe

```python
class Renard:
    """Un renard du refuge."""

    def __init__(self, nom, couleur, age):
        self.nom = nom
        self.couleur = couleur
        self.age = age
        self.energie = 50
        self.proies = []
```

| Morceau | Rôle |
| --- | --- |
| `class Renard:` | Déclare une nouvelle classe nommée `Renard` |
| `"""Un renard du refuge."""` | La docstring de la classe |
| `def __init__(self, ...)` | Le **constructeur** : la méthode appelée automatiquement à la création de chaque objet |
| `self.nom = nom` | Crée un **attribut** `nom` dans l'objet et y range la valeur reçue |
| `self.energie = 50` | Un attribut qui ne vient pas d'un paramètre : chaque renard commence avec 50 d'énergie |
| `self.proies = []` | Chaque renard commence sans aucune proie attrapée |

> 📌 **Convention** : le nom d'une classe commence par une **majuscule**, et chaque mot aussi : `Renard`, `RenardArctique`, `RefugeFaunique`. C'est le style *PascalCase*. Les variables, fonctions et méthodes restent en `snake_case`.

> ⚠️ `__init__` s'écrit avec **deux** traits de soulignement de chaque côté. Avec un seul (`_init_`), Python ne l'appelle pas, et les attributs ne sont jamais créés.

## 3. Créer des objets

On crée un objet en appelant la classe **comme une fonction**. Les arguments sont transmis au constructeur :

```python
class Renard:
    """Un renard du refuge."""

    def __init__(self, nom, couleur, age):
        self.nom = nom
        self.couleur = couleur
        self.age = age
        self.energie = 50
        self.proies = []

roux = Renard("Roux", "roux", 3)
flocon = Renard("Flocon", "arctique", 2)

print(roux.nom)
print(flocon.couleur)
print(roux.energie)
print(type(roux))
```

```text
arctique
50
<class '__main__.Renard'>
```

- `roux` et `flocon` sont deux **objets** (on dit aussi deux **instances**) de la classe `Renard`.
- On lit ou modifie un attribut avec un **point** : `roux.nom`. C'est l'équivalent de `renard["nom"]` pour un dictionnaire.
- Chaque objet a **ses propres** attributs : modifier `roux.energie` ne change pas `flocon.energie`.

```python
roux.energie = 80              # modifie l'attribut d'un seul objet
roux.proies.append("mulot")    # proies est une liste : on peut y ajouter
print(roux.energie, roux.proies)      # 80 ['mulot']
print(flocon.energie, flocon.proies)  # 50 []
```

### Le rôle de `self`

Quand on écrit `Renard("Roux", "roux", 3)`, Python :

1. crée un nouvel objet vide;
2. appelle `__init__()` en lui donnant **cet objet** comme premier argument, `self`, suivi de nos trois arguments;
3. renvoie l'objet, maintenant rempli.

`self` veut donc dire « **l'objet en train d'être construit** » (ou, dans une méthode, « l'objet sur lequel on a appelé la méthode »). `self.nom = nom` se lit : *range la valeur du paramètre `nom` dans l'attribut `nom` de ce renard-ci*.

> ⚠️ On ne passe **jamais** `self` soi-même : Python le fait. Le constructeur a 4 paramètres (`self, nom, couleur, age`), mais on l'appelle avec 3 arguments.

## En résumé

- Une **classe** est un plan; un **objet** est une chose construite à partir de ce plan.
- `class NomDeClasse:` définit une classe; son nom est en *PascalCase*.
- Le constructeur `__init__(self, ...)` crée les **attributs** de chaque objet avec `self.attribut = valeur`.
- On crée un objet en appelant la classe : `roux = Renard("Roux", "roux", 3)`.
- On lit ou modifie un attribut avec un point : `roux.nom`. Chaque objet a ses propres attributs.
- `self` est l'objet en train d'être construit; on ne le passe jamais soi-même.
